# XRM 三 Agent 实机可用性测试：根因修复执行提示词

你现在是 XRM 本轮可用性修复的实现负责人。请读取所附七份报告，核对当前源码和构建，实际修复、运行并交付。不要仅生成计划、重新打一遍设计分，或者再次推倒整个 TUI。

## 1. 授权、保留项与安全边界

允许修改本任务相关的组件、页面、CLI、客户端错误呈现、测试和规范；如确实需要后端提供已存在但未传达的错误事实，允许最小兼容扩展，必须说明原因和合同测试。不要借机重写 xrmd、换框架或建立另一套配置权威。

必须保留：

- C++23、FTXUI、CLI11、xrm/xrmd 分层、独立 Xray-core。
- 原生多文件 confdir、节点/订阅库存与 Profile/运行配置的边界。
- 三层导航；Tab/Shift-Tab 在当前层切换，Enter 进入下一层并消费，Esc 一次处理当前层。

- Profile 元数据 CRUD 不依赖模块 Edit。Edit 关闭时所有模块写入口只读。
- Visual/JSON 共用草稿；未知字段、原生类型和有语义的数组顺序保留。
- 子对象合入父稿、模块保存 Source、显式 Connect/Apply 发布运行配置的边界。
- 保存不隐式 Use/Connect/Restart；退出 TUI 不停止核心。
- 主页面不恢复常驻快捷键长条或右侧动作面板；操作发现集中于 Help，状态/对象说明集中于底部。表单内部的标准按钮与字段控件继续允许。
- 输入中的 q/e/u/c/d/p/? 等属于输入，不被全局动作抢走。
- 离线缓存/unknown、失败留稿、自动恢复连接、最小尺寸保护等已成立的行为。
- 现有 UUID 调用、非 TTY TSV、JSON 字段/类型、明确退出码及非交互 CLI 的兼容性，除本提示词明确授权且有文档说明的 stdout-consumer-close 策略调整。

所有实验只用本轮创建的独立 socket、数据库、HOME/XDG、runtime confdir、端口和 PTY/tmux 会话。不得操作生产订阅、真实用户节点、系统网络、TUN、防火墙、systemd 服务或用户正在运行的核心。

**不要复制 C 清理陌生 /tmp 构建目录的做法。** 没有进程占用不等于你拥有删除权限。磁盘不足时报告空间/inode、使用获准的其他临时根目录，或者申请必要权限；只能清理本轮有所有权清单的产物。

## 3. UXR-01：焦点、事件消费、弹窗与草稿退出

对应 C 的 Esc/导航锁死候选，B 的子层 Ctrl-S/焦点问题，以及 A/C 的集合焦点分歧。

### 3.1 用单次事件和明确状态确认问题

在干净 lab 中，一次发送一个控制键，观察当前格，等待明确状态；再另做有界的快速输入测试。记录输入键、实际字节、焦点所有者、打开的 overlay、目标对象及 draft revision。

不要凭 `Doma│` 一类残留字符认定表单真的重开；同时确认实际交互状态。也不能只因源码看似消费了 Esc 就拒绝复现用户轨迹。

### 3.2 若复现则修复根因

- 活跃的最上层 modal/editor 优先处理输入；一个事件只产生一次层级变化。
- 关闭 overlay 的 Esc 不落入父级重新打开同一个 overlay，也不继续关闭父层。
- 打开确认框的 Enter 不在同一次事件中触发确认按钮。
- 焦点上下文变更后，旧回调/悬空引用/旧 action 不再处理当前按键。
- 干净表单取消回到确定的父级；dirty 表单提供 Save/Discard/Continue，三条分支都可操作。校验失败留在原稿，不存在必须重启 TUI 才能离开的状态。
- 关闭 Help 返回原焦点控件、对象与滚动位置；刷新和异步回调不抢焦点。
- Profile 的导航 Enter 与 Content View 分开；View 不顺便跳 Modules/Use/Edit/Run。

### 3.3 Ctrl-S 必须有唯一提交所有者

为对象子表单、集合编辑层、模块工作区、JSON 编辑器分别定义提交目标和文案。一个 Ctrl-S 最多处理当前编辑范围一次：

- 对象表单只把该对象修改合入父稿，不同时写 Source。
- 模块工作区的保存才调用 Source 保存。
- 无可提交内容、只读或缺 Edit 时不能假成功，需提供适度、可理解的当前状态说明。
- 不能通过把 Ctrl-S 做成无条件全局 Source Save 来“修复子层不生效”。

用更具体的界面上下文名区分“模块工作区 / DNS 服务器列表 / DNS 服务器表单”等；内部仍可保持同一个 Content 枚举，用户不需要猜它的子状态。

## 4. UXR-02：修复公共输入与选择组件的可预测性

这是本轮最高优先级之一。不要在 DNS、routing、Profile 和 Group 各写一个特判。

### 4.1 Select：显示值必须等于当前表单值

本轮优先采用一个统一规则：获得焦点的选择控件切换合法选项时，立即更新**当前表单草稿值**，不存在未说明的隐藏“候选已显示但需要 Enter 才算选择”。这不是保存 Source，更不是应用运行配置。

当前控件若用横向 `‹ ›`，Left/Right 必须真实支持切换；不要让提示与行为矛盾。其他方向键仅按统一控件契约处理，不能泄漏给顶层导航。

- 失焦、Tab、Ctrl-S 后，提交的值必须与刚才显示的选项相同。
- Enter 不再承担不可见的第二次提交；不能同时触发父表单保存。
- 空选项、仅一个选项、不可用选项必须有准确状态。没有目标时说明缺的是什么和如何补充，不做一个无响应的假选择器。
- 若项目确有需要预览/确认的复杂 picker，必须明确区分预览与已选并提供显式 Apply/Cancel；不能让同一个基础 Select 在不同页面偷偷采用两套语义。

### 4.2 可选字段：缺省不是空字符串，也不是吞键

- 未设置的字段必须明显呈现未设置/不可输入状态，不能看起来可写却静默吃掉字符。
- 切换为显式值后，下一次正常 Tab 能进入输入框；不要求隐藏的 Right 键才能进入。
- 焦点不能被强制跳回 presence checkbox 并丢弃输入。
- 保留 omitted、显式 false、0、空字符串等真实区别；不要自动填充未获依据的 Xray 默认值。
- 在当前未保存草稿里暂时关闭/重新开启字段，可保留用户刚输入的候选值便于恢复；序列化时未设置字段仍按原生省略语义处理。

### 4.3 Checkbox 和 Enter

制定确定性规则，不猜“用户可能在找按钮”。本轮 Checkbox/Toggle 用 Space 改值；Enter 不再无提示地切换高级字段，不冒泡成整表单提交。统一更新控件 Help 和测试。

保留文本域 Enter 换行、按钮 Enter 激活、集合行 Enter 查看、导航 Enter 进入等明确焦点上下文行为。不要试图让全产品 Enter 只剩一种用途；要让当前焦点的用途可见且互不穿透。

### 4.4 子表单输入不能漏测

重复测试独立 TextInput、可选输入内的 TextInput、集合 New entry、routing port、订阅 URL 和多行编辑器。检查 Left/Right/Home/End/Backspace/Delete、插入中间、长文本与直接 UTF-8。

B 的 End 失效须在它实际的子表单上下文复验；不能以独立输入框 PASS 关闭。Ctrl-A/Ctrl-U 不在本轮新增范围。

## 5. UXR-03：长表单、校验定位与渐进呈现

不要删掉原生字段来减少 Tab，也不要回到“填一个字段按 Enter 再问下一个”的 Prompt 链。

### 5.1 常用任务先完成，高级字段仍完整可达

- DNS 将最常见的地址设置与匹配/回退/高级项分组。
- Routing 清楚组织匹配条件、目标、高级项；目标选择不能藏在看不懂的复合焦点链里。
- 常用/高级分区可以折叠或提供表单内分区导航，但仍是同一份完整多字段表单。
- 表单级分区导航与文本编辑器自己的文档移动不要抢键；不把 Ctrl-End 在文本输入里强行改成跳表单底部。
- 表单字段序号只表达字段位置，不能暗示“按 N 次 Tab 就到 N 字段”。可为字段搜索/跳转选用现有组件能力，不另造全局导航系统。

### 5.2 字段级错误可以直接修

- 校验结果应有字段/复合组定位和人读原因，不只是一个 form-level 字符串。
- 提交失败时把第一个需要修正的字段/组展开、滚动到可见并聚焦；不丢其他输入。
- routing 缺 outboundTag/balancerTag 时，定位实际 target 组。区分“用户尚未选择”和“当前没有可选目标”。
- 修改相关字段后及时清除或重新计算旧错误；关闭可选高级字段后，已不适用的错误不能继续阻塞提交。
- 跨字段约束重新检查相关组，不需要每个字符都做网络请求；未触碰字段也不必在用户刚输入一半时满屏报错。
- 异步校验结果关联对象/草稿版本，不能把上一版请求的错误贴到新值上。

### 5.3 原生保真与错误文案

库异常不是默认界面。高级 JSON 校验要说明哪个字段、语法位置（可确定时）和如何修复；原始异常可在诊断详情中查看。

不要仅因报告觉得 `webhook` 奇怪，就删除该字段或断言它非法；核对当前固定核心与项目原生表单依据。也不要用“只允许 IP”的简陋检查拒绝 Xray 合法的 DNS 地址形式。

涉及原生字段/默认值/合法取值时，只依据项目实际采用的官方 Xray 文档和固定核心验证；需要核验时读取 `https://xtls.github.io/llms-full.txt` 相关部分，未提及就明确不能确认，不编字段或自动改模型。

## 6. UXR-04：CollectionEditor 与草稿驱动的预览

### 6.1 行选择、按钮焦点和对象身份

- 明确区分行高亮与键盘焦点；有无颜色都能理解当前会操作哪一项。
- 表格/list 与按钮组可通过同一套明确规则进入/退出，Help 返回后仍可找到行。
- 两项及以上时，可选择第二项并执行 View/Edit/Copy/Delete；reorder 上下两向在合法位置可用，边界有原因。
- 重排后选择跟随同一个对象；删除后合理选择邻项，不按旧索引误操作另一项。
- 原生数组没有 ID 时使用仅限 UI 草稿的稳定身份/映射，不向原生 JSON 塞管理器 ID。
- 删除确认显示可识别的值/名称或原生摘要，不能只说 entry 2；位置可作为补充。

按钮、Help、快捷键允许是同一个动作的不同入口，**不必为了“一套范式”删掉所有按钮或快捷键**；必须共享 action、目标、可用条件和提交路径，不形成三套逻辑。

### 6.2 应用后立即看到同一份草稿

- 子表单 Add/Apply 完成后，父集合、计数、选择、模块预览与 JSON 必须同步到同一个 draft revision。
- 禁止从尚未保存的服务端 Source 刷新覆盖新父稿，也不能靠关闭重开才能修复 No entries。
- 不用“自动保存 Source”掩盖预览过期。
- 向集合添加成功后，清空新的输入缓冲并按统一规则设置焦点；添加失败保留内容。
- 不擅自去重或重排原生集合，重复项是否允许由该字段真实语义决定。

B 所谓 Cancel 丢稿已经被其复核更正：本轮需要验证取消保护和预览真实性，而不是假设存在无保护 Cancel 然后再套第二层 guard。

## 7. UXR-05：保留导航契约，修复 Help 与跨页指路

不因报告想用方向键/数字跳页就恢复另一套导航。也不要强制把每次打开 Help 记成缺陷；真正要修的是 Help 返回后仍不知道怎么继续。

### 7.1 每一层 Help 都有信息，不必 F1→Enter→F1 才理解页面

TopNav、SecondaryNav、Content、只读集合、字段、表单、确认框都要说明：

- 当前所在页/对象/可操作范围。
- 当前焦点下 Tab/Enter/Esc 实际作用，例如“页面导航”“模块选择”“字段编辑”，而非只给 TopNav/Content 内部词。
- 这一页能完成的任务，以及下一层如何进入。
- 当前前置条件、为什么只读/不可用、如何解除阻塞。
- 当前保存/取消到底影响表单、父稿、Source 还是运行实例。

低层尚未获得焦点的内容动作可以作为任务预览，但不能在顶层直接执行；区分说明行、导航行、真正可执行动作行，不显示无 key/无行为却看似按钮的悬空行。

### 7.2 只读恢复必须进入嵌套 Help

Modules 的 READ ONLY 原因不能在打开 Collection/Form 后丢失。

在只读场景中说明具体 Profile、Edit 前置条件，以及去 Profiles 开启该 Profile 模块 Edit 的路径。可在 Help 提供定位对应页面/对象的导航项；**导航本身不自动开启 Edit，不改变 Use，不保存或连接**。开启仍由明确的现有 Edit 动作完成。

跨页指路至少覆盖：Profiles 找 Connect、Modules 找 Edit、Logs 找 Stop、Overview 找添加节点、Nodes 找 Profile Use、Config 找原生 Modules、寻找 Groups。

这些是 Help 内的指路/导航，不是恢复每页跨上下文 c/d 等隐藏运行键。

### 7.3 焦点与合理反馈

- 在当前焦点区域给足够明显的焦点标识，同时底部使用人读的上下文名；不只改变一个难懂 token。
- `q` 仍仅在允许的退出层生效。非输入上下文中，首次/重复的明显错位操作可给去重、限频的短提示或 Help 指向。
- 不对每个未知字节都弹 Toast，不监听/回显用户在输入框里的文本，不把转义序列拆开误报。
- 已查看同一对象、刷新无变化等使用轻量反馈，不制造成功通知风暴。
- Help 文本可滚动、换行且有溢出提示，修复 ConfirmConfirm/DiscardDiscard 等组合重复；动作别名合并展示。

通知历史的入口要在有意义的 Help 上下文可达，不要求用户记住一个偶然看到的 N。

## 8. UXR-06：离线状态与动作可用性必须一致

报告证明缓存/unknown/自动重连已有良好基础，保留它们，修复动作和恢复层。

- 动作定义区分：纯本地查看/导航、修改本地草稿、服务端读取、服务端写入、运行生命周期。
- daemon 不可达时，不要把服务器写入或生命周期动作显示成可执行。Help 可保留任务但必须禁用并说明原因。
- 不要粗暴用一个 fresh=false 禁用所有本地编辑、Help、取消、查看缓存和草稿操作。
- 缓存是否过期、服务是否可达、某个任务所需引用是否已确认是不同条件。根据动作实际要求判断。
- 派发前重新检查前置条件，不能只在打开 Help 时检查一次。
- Refresh/Retry 要有进行中及结果反馈；用户不能分不清没收到按键还是刷新失败。
- 首次离线 Help 给出实际 socket、检查端点和启动/连接测试 daemon 的可行路径。不能猜测系统存在某个 systemd unit，也不擅自启动生产服务。
- 重连后刷新状态，不自动重放 Save/Delete/Connect/订阅更新。写入结果不明时使用已有 operation/result 查询核实，不能盲重试。

断线时已编辑的草稿继续保留；保存可明确拒绝并说明原因，不清稿、不显示 false success。

## 9. UXR-07：订阅结果必须保留实际原因，URL 必须可安全编辑

### 9.1 从任务结果追到每个 UI/CLI 出口

核对 operation envelope、每个 source 的结果、轮询、摘要、详情、通知及 CLI formatter。外层 operation 成功不等于每个订阅更新成功。

分别覆盖：全部成功、部分成功、全部失败、URL 语法错误、连接拒绝/超时、HTTP 错误、解析错误、对象不存在。

- 具体失败原因和阶段不能在 `failed[]` → summary → Details 的过程中消失。
- TUI 行/通知给短原因；详情给对象、发生阶段、上次成功、此次失败原因和下一步。`inspect source result` 必须真的能找到所指结果。
- CLI 不能把下载/HTTP/解析失败套成“对象不存在”。
- 失败不清空旧节点，不覆盖最后成功信息；明确旧库存与此次尝试的区别。
- 若查询接口不足，最小兼容地补足任务结果事实；不能以“后端不能改”为由编造原因。
- 若用户重新打开后无法获取旧错误，准确说明“未保留该次诊断”，不要声称不存在错误。优先用已有持久结果；确需新增持久字段时使用项目现有迁移方式，不临时绕过数据库合同。

### 9.2 URL 校验和揭示

- 保存前进行与当前支持来源类型匹配的语法校验；不访问网络就能识别的无效输入，应就地说明。
- 不因为一次下载失败而判 URL 语法非法；不发明仅 HTTP 可用等限制，按现有来源能力核对。
- 订阅 URL 可能含凭据，不能沿用“URL 一定不是秘密”的评审假设。
- 默认列表、通知、日志和报告继续脱敏；实际编辑器始终持有真实值。
- 在秘密字段旁明确隐藏状态和可发现的 Reveal/Hide 控件/说明；现有 Ctrl-R 可继续作为同一动作的加速键，不要求先聚焦再碰巧打开 F1 才知道。
- 掩码不是模型值；切显隐不修改草稿、不移动文本、不把圆点保存回去。关闭后恢复安全显示。
- 错误定位可以展示安全的 host/路径摘要，但不把 token、密码、认证头或完整凭据泄漏到证据文件。

## 10. UXR-08：错误需要任务上下文，不是 code 到一句万能文案

实现或完善统一的人读错误层，输入应包括命令/动作、目标对象、失败阶段、已确认结果、原始 cause 和可行恢复方式；不要只根据一个共享错误码猜原因。

至少修复：

- `core.register` 验证 `/bin/true` 等非 Xray 可执行文件失败，不能说“修改保存的候选配置”。
- 已登记真实核心的配置检查失败，才指向相应 Source/校验错误。
- 订阅对象不存在与 HTTP 404/下载失败不是同一种 not-found。
- UDS 不存在、权限错误、连接断开、写入结果不明按实际已知事实表达。socket 不存在不自动等于“系统服务一定没有启动”。
- 原生高级 JSON 错误不默认打印整段 nlohmann 异常。

用户首先看到任务、对象、原因和下一步；原始混合语言/errno/内部方法名留在明确的诊断详情或详细输出中，不在默认人读结果后重复粘贴一大段。

`--verbose`/诊断入口先核对现有功能；需要新增则只设计一套一致入口并加测试。保持原始诊断可达，不把翻译后的推断冒充原始 cause。

不要为清理英文界面而擅自改变 wire JSON 的字段名、类型、错误码；机器客户端应继续能按 code 处理。若改变人读 message，明确记录其范围，不声称原始外部日志已被翻译。

成功后附加查询失败不能把已成功的写入说成没执行；不确定结果要明说待确认。

## 11. UXR-09：状态作用域、对象身份与可读名称

### 11.1 不合并状态，只把它们讲清楚

底部用明确的名词/状态标签区分正在查看、下次连接选用、模块编辑上下文、实际运行。不要把 `Use Alpha` 写得像现在会执行的命令。

高亮对象与 View 可以不同；应分别标识“当前行/操作目标”和“查看中的 Profile”，不要为了看似同步而改成方向键移动就自动 View/Use。

跨页返回保留合理的 Nodes scope/来源/选择；若设计确需回到 All，显著且一致地反映它。`1/4` 与 Groups 内容必须来自同一个导航状态，不能各维护一份索引。

### 11.2 Saved 与 Running 只有可比较时才能判断差异

- stopped 且无运行目标：以“下次连接使用…”表达，不告警“与正在运行的目标不同”。
- disconnected/unknown：不装成 stopped，也不假定 actual none。
- View B、Run A：先明确两个 Profile 不同，不拿 B 的保存配置去指控 A 运行异常。
- 同一 Profile 的保存与运行快照确实不同：说明尚未应用的差异；正常未应用修改不自动升级为故障。
- Group 保存目标与实际选中的成员、临时 override、运行快照是不同概念，不能用简单 ID 不相等就报警。
- Connect 后的刷新以可信 operation/runtime 结果和正确 Profile 为依据，不拼接旧 View 缓存形成自相矛盾状态。

### 11.3 名称优先，但原生 tag/ID 不能丢

- TUI 节点列表区分同名对象的来源/协议/必要短 ID，详情给完整稳定 ID。
- Routing 目标可显示已可靠解析的节点/组友好名，同时让用户看见实际原生 tag；不能把名字写回替换原生 tag。
- 未解析的原生 tag 原样保留并诚实标识，不伪造名称。
- 人读状态优先对象名，ID 作为可引用补充；机器输出不跟着改顺序/结构。
- Create/Add 与 Edit 标题区分创建/修改；“模块 Edit 状态”与“当前表单正在编辑”不共用一个没有对象的 EDIT 标签。
- Group 摘要在已有数据支持时显示成员数量/来源范围，不只有 `explicit` 一个内部词。

不要让 CLI 去修改或读取另一个 TUI 会话的 Use/Edit，不能为统一显示把它们变成全局持久状态。全局 status 与指定 Profile 查询仍有不同作用域。

## 12. UXR-10：有后果的动作与确认焦点

这是本轮明确的 TUI 防误操作改进，不将它写成过去已经承诺/实现的事实。

- Profile/节点/组/来源等破坏性确认默认聚焦 Cancel/安全选项，Enter 在未切换确认按钮时不删除。
- 说明实际目标以及当前能够确认的影响/引用；不可得的数量不能编，后端拒绝条件不能说成必定级联删除。
- TUI Stop/中止当前启动操作在执行前给明确目标和后果确认，默认取消；当前无运行/启动实例时给准确 no-op。
- 无论快捷键还是 Help 选择 Stop，都走同一条确认与派发路径，不能一条绕过、一条重复确认。
- 确认时绑定实际运行身份；等待期间运行实例变化，不能误停一个新实例。
- 不把自动重连当作“撤销 Stop”，不在用户取消后偷偷重放。
- CLI 保持显式、非交互：不把 TUI 的确认弹框变成脚本等待 stdin。已停止时正确说明 Already stopped，不声称刚停掉一个核心。

no-op 判定必须基于操作返回的可信事实或经过核实的状态；不要仅凭可能过期的前置 status 猜测本次做了什么。

## 13. UXR-11：整屏合成、窄屏、日志与通知结果

本轮只修测试指出的可用性/表达问题，不另开整套皮肤重设计。

### 13.1 浮层与小屏

- Dialog/Help/Toast 在自己的矩形内完整绘制背景，含空白和 padding；底层在浮层范围外可见不自动等于穿透缺陷。
- 开/关/移动/Toast 到期后底层正确重绘，无文字残影、重复边框或旧字符。
- 80×24 的 SectionTree 不退化为单字符碎片；采用合理最小宽度、折叠/单视图选择与可达详情，不抬高最低尺寸来绕过问题。
- 长 Select 核心版本选项摘要与完整详情分离，禁止溢出；路径截断有明确省略且可查看原文。
- 同进程 resize 保留当前对象、父子草稿、光标和焦点；不重启程序冒充恢复。

### 13.2 Logs 的原始事实不能为了好看被改写

核对日志实际来源、原始级别、解析器和合成消息：

- 若“Xray started”本来就是核心明确输出的 Warning，保留原始级别，不为消除黄色改成 Info。
- 只有 manager 自己错误赋级、把 stderr 一律当 Warning、或解析器错误推断时，才修正对应归因。
- 未提供时间不造时间；显示 `—` 本身不等于缺陷，要让其含义可理解。
- 传输 chunk、逻辑记录、视觉折行分开；不把传输序号冒充记录号。
- 长消息续行对齐 message，不能落到 SOURCE 列看似一条新记录；原始详情可完整读取。
- 日期/时区在摘要与详情中的关系明确。技术传输字段可放诊断详情，不和主消息同权。
- 保留 Following/Pause、缓存/断线标识、未知格式、缓冲上限与 dropped/truncated 的真实语义，不伪造计数。

### 13.3 Toast 不承担唯一证据

保留右上角、不抢焦点、自动消失的通知。失败原因、保存结果、正在进行/已结束的任务至少能从对应对象/任务详情或通知历史重新查看。

历史有清楚入口、动作目标和完整安全诊断；不要只是让用户看一个过期的 `! Error`。表单错误就地保留，不因 Toast 消失而消失。

## 14. UXR-12：CLI 失败流、部分成功和 stdout 消费者关闭

### 14.1 订阅更新的语义与输出流

同一构建分别捕获 stdout、stderr、退出码，核对 source 全失败/部分失败及 outer operation 状态。

- 默认人读的全部失败：错误/恢复信息到 stderr，不向 stdout 输出假成功。
- 部分成功：结果与失败诊断分开，保留已有正式定义的部分失败退出码；不能因任务调度成功就 exit 0。
- `--json` 与非 TTY 模式按现有正式合同输出；发现实现把错误流发错，按合同修正并加回归。
- 若某种聚合 JSON 的流位置本来是正式兼容约定，不能在“清理人类提示”时悄悄改变。记录现状、必要修复及兼容边界，不改字段类型或丢部分成功数据。

### 14.2 明确区分两种 broken pipe

1. xrm 向 xrmd 的 IPC 写/读失败：仍是需要用户处理的错误，stderr 有原因，非零退出；写入结果可能不明时说明待确认。
2. xrm 向 stdout 写入时，下游 `head` 等主动关闭：属于输出消费者结束，不得误报 daemon/IPC 错误。

本轮为常见采样管道选定统一策略：**仅确认 stdout 的 EPIPE/消费者关闭时，安静停止 watch 并正常结束；不再把它映射为 daemon io_error/exit 3。** 这是显式的 CLI 行为调整，需要更新相关文档与旧测试预期。不要吞掉其他 I/O 错误或已先发生的业务失败。

检查进程/库级 SIGPIPE 处理的作用域，避免一个全局 ignore/default 修改意外改变 IPC 行为。停止后不继续 RPC 轮询、不反复写 stderr、不 busy-loop。

测试记录每个管道进程的退出状态以及 pipefail 开/关，包含：human watch、JSON watch、`head` 提前结束、下游仍在但 daemon 真断开、普通 `| cat`、SIGINT、stdout 非 EPIPE 写入失败。报告原始观察 0/141/3 的差异，不能用 shell 最后一个退出码抹平。

## 15. UXR-13：CLI ref、JSON 输入与人读输出

### 15.1 资源引用习惯

对报告明确涉及的订阅 show/edit/update/remove 等现有入口，核对是否只接受 UUID、帮助是否误导。

本轮允许在保留 UUID 的基础上，增加**精确且唯一的名称**解析：

- 使用同一 socket/资源范围查询，不能跨 Profile 解析一个 Group，不能把订阅当 Profile。
- 已存在的精确 ID 优先；名称精确匹配，重名报歧义并给可选择的 ID，不 fuzzy 选第一项。
- 对未支持名称的接口，明确说明实际 ref 约定和获得 ID 的命令，不谎称列表里存在的名称对应对象“不存在”。
- 端点不可达不是“名称不存在”；失败阶段必须正确。
- 不修改原生 Xray tag 的引用规则，不把所有 tag 都替换成显示名称。

### 15.2 大 JSON 不只依赖 shell 转义

为当前 `config edit --text` 提供兼容的 file/stdin 输入。先核对已存在选项，必要时按 CLI11 当前项目方式加入等价入口，例如 `--file PATH` 与 `--file -`；这是新增方案示例，不是假定现有命令。

- 旧 `--text` 继续可用；多个输入来源互斥，错误说明清楚。
- stdin 仅在显式请求时读取，不让普通命令突然等待。
- 完整读取并校验后才发保存请求；文件/JSON 错误不造成部分写入。
- 原始类型、顺序、未知字段和保存边界仍按现有流程处理。
- 不把含凭据配置回显到默认错误、日志或执行报告。

### 15.3 人读格式与机器格式分别验收

- 用真实 TTY 验证 profile/core/sub/node/group list、show、status 的名称、空状态、时间、列与回执。
- 以实际非 TTY TSV、`--json`、watch 格式分别验证兼容；不能把 A 已纠正的 UUID-first pipe 输出再改成人类表格。
- TTY 中可改进 names-first 和可引用 ID、可读时间、空日志/空 core 列表；非 TTY 原本空输出/epoch/列顺序若是合同，不擅自插入标题或 No results。
- stop 已停止、对象未变化等结果准确表达；不要为了文案通过而谎称发生修改。
- `logs --help` 对已存在 `--cursor`/`--limit` 解释真实单位/语义/默认值。没有 --follow/--tail/--level 本身不等于 bug，本轮不因评审随口列举就扩功能。
- TUI Config 与 CLI config 的历史范围可在帮助里对应说明，不强行重命名破坏命令兼容。
- 清理默认人读内部枚举/无意义模板尾注，保留必要恢复信息；不能把同一个名词对应的不同领域状态硬合并。

## 16. 实施顺序与交付方式

1. **短基线与分歧复现。** 核对源码/二进制，安全 lab，记录初始最小失败轨迹。
2. **共同根因优先。** UXR-01/02/03/04 的实际阻塞先修；UXR-07 的诊断丢失和 UXR-05/06 的恢复路径可按代码所有权并行。
3. **统一接入。** 七页、所有使用公共控件的表单、Help 和 CLI 同步，避免只修 DNS 示例。
4. **表达与安全。** UXR-08/09/10/11/12/13，修确认、状态、错误流和 shell 边界。
5. **回归与新的黑盒复验。** 先工程验证，再让未读修复答案的独立上下文完成任务；记录仍有的摩擦。

更新一份唯一交互契约和项目 Skill 引用，明确本轮有意修改的 Select 草稿提交、Checkbox 键语义、Stop 确认、stdout EPIPE 策略和 CLI 新输入/ref。不要让旧提示词、旧测试和新规则同时被当作权威。

并行 Agent 必须共享接口/状态/组件契约，有明确文件所有权；不要几个人同时修改同一个表单核心或使用同一个 lab。

不得在设计文档或安装工具完成后停止。若部分环境受阻，明确隔离影响并继续其余安全工作，不伪造完成。

## 18. 黑盒复验不能由实现者背答案代跑

工程测试后，在宿主支持时启动新的独立 Agent 上下文。测试者只获得安全操作规则、启动入口、fixture 卡和用户任务，不先看问题清单、源码、修复记录或全部快捷键。

让测试者自己用当前界面/Help 完成至少：

1. 找到另一模块，从只读恢复到可编辑。
2. 新增 DNS 服务器；新增 routing 规则并故意漏 target 后修正。
3. 修改第二个集合项、排序、取消一次、保存一次。
4. 诊断一个失败订阅并局部修正 URL。
5. 服务断开时判断哪些动作还能做；恢复后继续草稿。
6. 连接固定测试核心、看日志/统计、明确停止。
7. 用 CLI 找订阅、按名称/ID 查询、提交文件配置、采样 watch 管道。

修复者/观察者可以在旁路查询隔离 RPC/文件核实结果，但不能把源码答案喂给黑盒操作员。

如果宿主不能开启新上下文，或强制注入了完整设计规范，就标为“受指导复验”，不能假装首次盲测。多个 persona 在同一上下文不是多个独立新用户。

记录实际按键、返回/错路、Help 次数、任务是否完成和界面给出的恢复路径。不把 LLM 思考耗时或工具延迟当成人类反应时间，不虚构“真人犹豫了三秒”；帮助使用次数也不是越少越好，关键是是否解决任务。

## 20. 最终交付与完成定义

交付实际代码、测试与少量不重复的文档。建议使用项目已有目录；没有合适文件时可新增：

- `docs/usability-repair-execution.md`：基线、UXR 追踪矩阵、变更、兼容性、测试与黑盒结果。
- `docs/evidence/usability-repair/<run-id>/`：当前格、必要 ANSI/图像、命令的分流输出、按键轨迹和来源 manifest。
- 更新唯一交互契约、组件规范必要章节与人工验收清单。项目 Skill 只引用权威，不复制第二套完整规则。

证据 manifest 记录：源码/构建摘要、终端尺寸、真实/合成数据性质、fixture 身份、时间、输入轨迹、当前格和状态事实的关联。不要仅引用本机随时会消失的 /tmp 路径；可复制本轮自己创建的证据到获准目录，敏感内容脱敏。

每个问题记录：来源文件+条目、本轮复现结果、根因是否源码确认、修改层、验证命令、结果、未验证边界。对未复现项保留尝试过的焦点/时序/数据条件，不能只写“没问题”。

最终明确区分：

1. 工程回归结果。
2. 新独立黑盒复验的完成任务与仍存在的摩擦。
3. 工具/IME/真实网络等证据限制。
4. 用户 G5 人工验收仍未代签。

完成不是“增加了多少断言”“三位测试者分数提高了多少”，而是：原来失败的任务能用真实产品操作完成，用户能看到实际原因并修正，界面显示与草稿/保存/运行事实一致，公共修复覆盖全部受影响页面。
