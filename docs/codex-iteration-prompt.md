# XRM 下一轮迭代：交互组件、节点生命周期、测试与原生配置预设

**交给 Codex 的完整任务提示词 · 2026-09-25**

用户已经确认现有七页版本能正常导航、滚动、更新订阅、联网及查看日志，基本满足需求。现在授权一轮新的体验和功能迭代，不是重新把全部既有工作判为 G5 失败，也不是只改颜色。

请将本文件视为本轮新增和变更需求。与旧文档的“长期保留 source_missing”“只允许一个且绝不能有测试核心”“禁止可视化 JSON 编辑”“不得增加模板/资源管理”等限制冲突时，以这里的明确授权为准。没有冲突的 Manager/Server、节点库、原生模块和多文件边界继续保持。

## 0. 先研究实际实现，再做小步交付

先检查当前工作区、实现、依赖版本和已有功能，不重新实现已完成的协议、订阅 HTTP、核心安装或生命周期。实际回归继续使用项目已验证的 Xray v26.9.9；它是固定测试基线，不是永久“最新版”。不因本轮研究自动替换运行核心。

阅读本文末尾一手资料。配置字段先查 Xray 官方完整文档的相应章节，再核对固定核心源码及实际输出。参考 v2rayN 的测速、路由预设和资源选择，参考 xrat 的表格/焦点/布局，查看 Clash Verge Rev 官方预览中的信息分区。记录实际查阅的版本或 commit。

不能声称“看过截图”却只读 README；无法获取某个 GIF/截图就写明，仅以实际看到的画面和读过的实现为依据。参考用户提供的两张 XRM 截图：表头和行列错位、两级导航被分开、Overview 全部挤在左上角，是本轮具体改进对象。

不换 Rust，不引入 React/Ratatui，不重建前后端。允许为实际复用抽取少量 UI 组件和新增业务服务；不要再把“避免过度工程”解释为所有页面必须堆在一个大函数里。

## 1. 顶层架构和本轮页面归属

顶层保持七页：

```text
Overview | Profiles | Modules | Subscriptions | Nodes | Logs | Config
```

- 顶层/二级 Tab、焦点、通知、布局属于 Manager TUI。
- CLI 继续有自己的命令式 UX，共用业务 RPC，不通过调用 TUI/CLI handler 相互套壳。
- Node/Subscription/Geodata 资源目录及程序设置由 Server 管理。
- Profile 保存上网方案、来源/资产选择和管理绑定；原生模块文件仍是原生配置的编辑来源。
- 配置最终是多个原生文件；不新增全量 config.json 权威对象。
- Nodes 保留来源、Local、Groups 分类；Groups 不变成伪协议。
- Overview 继续包含统计；Logs 保留。
- Config 的二级页允许增加 Geodata 和 Tests，成为 Core / Geodata / Tests / Appearance / Editor / General。不要为新功能增加顶层 Tab。
- Profiles 提供模板、分流预设和资产选择入口；Modules 提供原生结果与编辑入口。同一个功能从多个入口打开时使用相同编辑器和应用接口。

## 2. 三段式界面：两级导航都固定在最上方

统一页面壳，按终端实际行列计算：

```text
┌ 顶部：当前方案/运行摘要（至多一行）──────────────────────────┐
│ Overview  Profiles  Modules  Subscriptions  [Nodes] ...       │
│ [全部订阅]  来源A  来源B  Local  Groups                     │
├ 中部：搜索/表头/表格/详情，或模块编辑，或Dashboard ──────────┤
│                                                            │
│                主要内容与滚动区域                          │
│                                                            │
├ 底部：当前焦点层级、简要状态、常用操作 ──────────────────────┤
│ 内容 · 49个节点   f搜索  s选用  c连接  t测试  ?帮助  Esc返回 │
└────────────────────────────────────────────────────────────┘
```

两级 Tab 必须紧邻，不把二级 Tab 留在中部列表容器里。无二级页时不强占多余空行。顶栏不能留下当前截图那样的大片无用途留白。

中部独立裁剪/滚动，顶部和底部固定。搜索栏和表头可固定在中部容器上沿。底部一般 1–2 行，只显示当前状态及最常用的 5–7 个操作，其他放 Help。一次性的更新成功、失败信息不得一直堆在底部挤掉操作提示。

所有页使用同一布局约束和主题样式，不要求每页机械地套相同内容布局。

## 3. 分层键盘焦点：同一个 Tab 在当前层级内工作

这不是实现 Vim 模拟器，只是明确一套小型焦点状态。

| 当前层 | Tab / Shift-Tab | Enter | Esc |
|---|---|---|---|
| TopNav 顶层导航 | 切换顶层 Tab | 进入该页 SecondaryNav；无二级则进入 Content | 留在顶层，不意外退出 |
| SecondaryNav 二级导航 | 切换本页二级 Tab | 进入当前内容区 | 返回 TopNav |
| Content 内容区 | 切换当前页的可聚焦控件/面板 | 打开详情或执行已聚焦按钮 | 无待处理编辑时回到 SecondaryNav/TopNav |
| Overlay 弹窗/编辑 | 在弹窗内部切换 | 按该控件含义操作 | 关闭/取消当前层；有未保存改动时给保存/丢弃/继续编辑选择 |

必须做到：
- 启动后焦点层级可见。当前 Tab 高亮与“焦点在哪一层”是两个不同标记。
- 在顶层 Tab 到 Nodes、Enter、Tab 切来源、Enter 进入表格、Esc 回来源、Esc 回顶层，行为可预测。
- 节点/订阅表格里上下移动行；PageUp/PageDown/Home/End 继续有效。Tab 不再意外切走顶层页面。
- 底部随焦点层级更新帮助。内容态提供 f 搜索、s 选择、c 连接、t 测试等；搜索/编辑输入期间这些字母只是文本。原有 / 搜索可保留兼容。
- 数字切顶层等已有快捷键若保留，只在合适的导航层生效，不在输入框、数值输入或弹窗中穿透。
- Help 支持 F1；非文本态可用 ?。退出只在明确的菜单/焦点上下文里触发。Esc 不是 stop，不应取消 Server 上已经接受的任务。
- 点击某个区域时同步焦点范围；鼠标滚轮只滚当前命中的可滚区域。没有鼠标也能完成所有功能。
- 外部编辑器回来、窗口缩放、任务完成，不能偷走当前焦点和未保存稿。

用 enum + 现有组件事件处理实现即可，不开发通用状态机/键位语言。新旧键位冲突由一个集中映射消除。

## 4. 右上角通知组件，而不是底部追加文本

实现终端内部的 NotifyOverlay，借鉴 mako 弹出感，但不是要求安装通知守护进程，也不把 notify-send 当唯一实现。

- 位于中部内容区右上角，紧贴顶部导航下方，不挤压布局、不抢键盘焦点。
- 状态包括进行中、成功、部分成功、失败；每个操作 ID 对应一个通知，阶段变化更新原通知。
- 有真实进度才用进度条；否则 spinner + 阶段文本。不要模拟百分比。
- 成功短暂停留；警告/错误停留较久且可看详情；错误详情还保留在对应业务页面，不因通知消失就丢失。
- 最多显示少量通知（例如3条），其余合并为摘要，不能无限叠加。
- 多次轮询同一 completed 不重复通知。应用初次读取旧状态不重新弹出历史成功消息。
- 通知出现、消失可以用短过渡；减少动效设置生效。没有通知动画/操作时不永久高频刷新。
- 模态弹窗之上不要堆遮挡输入的通知。过小终端使用紧凑通知，不越界。
- 底部只保留简短的当前状态，如当前模式、选中数、待应用修改。

## 5. 可复用的真正表格组件，表头与行使用同一列布局

节点表目前的问题不能用手工补空格修复。抽取一个小型 VirtualTable/DataTable（具体名按仓库），先用于 Nodes，再复用到订阅、核心和 Geodata。

列描述只需：key、title、最小宽度、优先级、对齐、伸缩权重、取值/渲染函数。不要开发另一套 UI 框架。

要求：
- 表头和每一行共用一次计算得到的列边界；固定/伸缩列混合，名称列优先利用剩余宽度。
- 按终端显示宽度而非字节数/std::setw 计算中文、emoji、组合字符；复用当前 FTXUI 能力，必要时少量针对终端宽度的适配，不写自制 Unicode 引擎。
- 表头固定，行区滚动；选中行始终可见。保留现有稳定 ID、分页和1205节点测试。
- 数字/延迟/速率右对齐，名称左对齐；未知显示 --，时间/单位有列含义。
- 小宽度按优先级折叠次要列，详情仍可查；必要时水平滚动，而不是列相互覆盖。
- 状态、名称、协议/传输、安全、来源、测试结果是默认可见内容，内部 UUID 和研发验证标签不挤占主表。
- 测速结果更新不应持续重排高亮对象；用户显式按测试列排序时也按 ID 保持选择。
- 空表、加载、失败状态各有正常占位。不允许靠截断总节点数让布局看起来正常。
- 添加一列只增加列描述及数据映射，不同时改每行字符串、表头和三份宽度逻辑。

## 6. 响应式 Overview、真实流量图和主题

不要继续把几十行文本放在左上角，也不要仅为了填空白放大字体。

建议布局（具体比例用实际截图检查）：
- 顶部内容区：连接/方案卡片与核心/入口卡片，宽屏并排，紧凑屏上下排列。
- 中部：上传/下载速率折线图或终端图形；标明时间范围、单位、图例及最新值。
- 下部：累计流量、时长、已选分流预设、资源版本/状态、最近必要操作摘要。
- 停止时仍保持合理分区，显示连接动作和需要准备的条件，不用十行 unavailable 堆在角落。
- 开发诊断文字、运行目录、process_only 等细节放展开详情，不做首页主体。

图表：复用真实 Metrics 快照与现有采样，保存有界的短时间序列（例如最近5分钟），不新建时序数据库。没有采样显示“等待数据”；缺失区间不能画成真实零流量；核心代际变化重置速率基线并标记间隔。若 Server 只在有观察者时采样，界面必须说明没有观察期间的历史并不存在。

定义普通布局断点：80×24紧凑、120×35常规、160×45宽屏，并额外测200×55。根据可用列数/高度调整卡片、图表和JSON双栏；不要写死像素，不只是固定宽度小盒子居左。

最小可用尺寸建议80×24。普通TUI不能跨终端可靠地阻止宿主窗口继续缩小：低于最小值进入 TerminalTooSmall 保护视图，提示当前与最低行列，保留会话/草稿/后台任务；放大自动恢复。过小时停止布局相关危险输入，不重启核心、不清空稿件。不要为此执行反复拉大窗口的终端控制序列。

主题集中为语义 token：背景/表面/边线/主次文字/焦点/选中/运行/成功/警告/错误。统一边距与标题层次；非颜色标记仍可辨识。提供终端色、深色、浅色/高对比等少量方案。字体家族和字号由终端设置，XRM只提供可兑现的字符、密度与样式配置。CLI --json/管道输出不混ANSI、通知和图表。

## 7. 节点库存：真正移除旧项，运行快照独立保留

这是本轮明确的数据语义变更，替代“所有已移除节点长期存为 source_missing 再靠 Show removed 看”的旧默认。

### 7.1 三类事分开

1. 完全等价的重复连接配置：同一来源内规范化去重，名称/查询参数顺序/已知无效默认项不单独制造连接身份。相同UUID但不同地址、传输或安全参数绝不是同一连接。
2. 订阅成功更新后已不存在的条目：从当前库存与普通持久节点记录移除，不只打source_missing标签，不在“All”里复活。
3. “剩余流量”“套餐到期”“官网”“距离重置”等订阅说明项：归订阅信息，不应一轮一轮制造可连接节点。

同一来源中真正连接等价但名字不同的重复，保留稳定代表ID和用户名称/属性，必要的别名可作为有限当前元数据，不保留多条同等节点。跨来源不默认合并；Local不参与订阅自动删除。合法不同连接不能为了降低数量错误合并。

订阅说明识别先使用可靠的来源元数据/响应头，再用明确、可查看和可关闭的来源级规则识别常见说明前缀。规则要有针对性，不是名称包含“官网”任意两字就删除。无法确定的条目给用户一次性分类选项；不能把不认识的数据当垃圾。提取不了结构化额度就保留当前说明文本，不编造数值。消失的旧额度文本不长期存成节点。

完整成功刷新才有资格确认移除；下载失败、错误页面、部分解析失败不能推断缺席条目已经删除。相同有效响应反复刷新与Server重启后更新必须幂等。

### 7.2 用户的 shared_ptr 比喻如何落地

当前核心运行的是已经加载的配置，不能依靠查询“实时节点库”来解释运行目标。

采用或复用：
- 当前库存：下一次选择/组装用的最新节点。
- 不可变运行快照：实际启动时的节点参数、显示名、选择、confs 与必要资源绑定。
- 运行记录持有快照；进行中的切换/回退或测试任务可暂时持有。

Server可用shared_ptr<const ...>管理内存所有权，但这不是跨进程共享指针，Xray不会持有C++对象。复用已有RunRecord和运行目录即可，不创建通用引用计数数据库。

当A从订阅移除但仍被当前核心使用：
- 库存不再列A，不允许新操作把它当最新节点。
- Overview仍从运行快照显示“正在使用A（来源已移除）”。
- 当前连接不重启，文件和PID不变。
- 下一次用户选择B并成功切换、旧进程退出且临时任务不再持有A，释放旧快照及其仅有运行用途的数据。
- 切换失败需恢复A时，在这次恢复决定结束前保留旧输入；不能先删掉再说可回退。
- 自动恢复当前实例用当前持有快照；Server重启也要能读取必要的当前快照，不依赖被删除的库存行。

不要为长期保存全部历史节点虚构引用。若现有显式回滚功能仍需有限快照，其保留范围、释放条件必须单独说明，不能让“存在一个旧Profile引用”永久保留所有节点对象。

源模块/显式组成员指向已删除节点时，保留一个可解释的“引用失效”状态，不保留完整旧节点冒充当前库存，不静默换人或直连。真正等价重复可以通过明确映射修复管理器引用；不能按名称猜测不同连接等价。

旧数据做一次性升级预览：哪些是确定冗余、哪些是说明、哪些仍被实际运行持有、哪些引用待处理。应用层确认一次即可，不再建多重c/y确认迷宫。先在副本验证，不清空生产库。旧“Show removed”应删除或改成独立诊断入口；不能用过滤隐藏冒充物理清理。SQLite删行不保证文件立刻变小，无需每次VACUUM或安全擦除。

## 8. Modules：二级模块Tab + 可视化JSON编辑 + 原文

Modules不再用“先选一条模块列表再进详情”作为主要入口。顶部第二行就是15个原生模块Tab，使用精确key，支持横向滚动和搜索选择器。禁用项有标识，但仍可进入。

选择dns等模块后直接看到相应JSON：
- 宽屏：左侧可视化字段/结构，右侧原生JSON实时预览。
- 紧凑屏：同一内容区切换“结构/JSON”，不能缩成两列不可读字符；不是再叠一条全局三级Tab。
- 显示included状态、源文件、草稿状态；运行JSON通过明确切换查看，不与源稿混同。

本轮明确允许一个小型可视化JSON编辑组件，不再受旧“全部高级字段都交外部编辑”限制：
- 对象添加/删除/重命名key，标量编辑string/number/bool/null；保留真正类型。
- 数组添加、删除、复制、排序；路由数组顺序是语义，不能自动排序。
- 常见模块用已有表单和少量字段描述提供标签、说明、选项、默认值建议。
- 未覆盖字段仍可通过结构树/原文编辑，不能丢掉。
- 所有15个模块都有实际可用的结构/原文入口，不是15套服务或假按钮。

实现使用同一份ModuleDraft/JSON DOM作为已解析草稿，JSON Pointer等只作内部编辑定位；不增加对外任意补丁平台、不下载全量schema、不自研JSONC AST/CST。

原文与表单切换：合法原文同步到同一草稿；原文无效时保留文本并指出错误，暂停不可靠的表单覆盖。未知字段保留。未编辑模块原文字节不变；表单确需规范化当前模块排版/注释时说明，保留外部编辑选择。

典型操作必须直观：添加DNS服务器、编辑hosts、增加/排序routing规则、选GeoSite/GeoIP资源标签、修改policy、增删入站、切观测类型。修改传输/安全仍写所属入/出站，不能变成伪顶层模块。

表单、原文、外部编辑都是同一可写数据来源。保存不自动连接；显式Apply才影响运行。Profile模板/路由预设改动也使用相同的预览差异和保存入口，让用户能学习JSON变化。

## 9. 节点测试：ICMP、TCPing、真实代理延迟，以及显式下载测速

本轮明确授权节点测试功能，不能再以旧阶段“测速都交核心”拒绝。测试集中在Server的一个小型NodeTestService，CLI/TUI共享；不在UI另做网络实现。

### 9.1 四种结果不混用

| 类型 | 目标及测量 | 不能说明什么 |
|---|---|---|
| ICMP Ping | 节点服务器地址的ICMP往返与丢包 | 不证明端口、TLS或代理认证可用 |
| TCPing | 节点地址:端口的TCP连接建立时间 | 不证明代理可用；纯UDP/QUIC节点不适用 |
| Real delay / URL test | 经选定代理节点访问指定HTTP(S)目标的实际耗时 | 不是ICMP，也不是带宽 |
| Download test | 经选定节点下载固定目标，记录字节/时间和速率 | 不是单纯延迟；结果受目标服务器影响 |

前三项是主要必需功能；下载测速提供明确的独立按钮和数据量/时间上限，不自动批量消耗全部节点流量。首版不额外扩展上传/UDP专项/压力测试平台。

结果包含类型、目标、样本时间、成功/失败/不适用/取消、延迟或速率。节点参数变化后旧结果标过期；删除节点后的迟到结果不能重新创建库存记录。ICMP被禁不等于节点离线，TCP成功也不标记“代理认证通过”。

ICMP可调用已有系统ping工具并直接argv执行，缺工具/权限时准确提示；不把Server提升root。调用参数先核对本机实现，子进程输出解析固定locale。TCP用现有异步连接能力，记录解析与连接计时边界。所谓直连探测实际遵循系统路由，启用TUN时不能虚称一定绕过代理。

### 9.2 Observatory能做什么

官方observatory/burstObservatory是HTTPing后台观测，不是ICMP/TCP/下载测速的通用代替品。[S1]

测试目标选择优先级：
1. 本次用户指定URL；
2. 选择“沿用当前Profile观测目标”时：observatory.probeUrl，或burstObservatory.pingConfig.destination；
3. Config → Tests 中XRM默认URL。

burstObservatory.pingConfig.connectivity是本地网络诊断目标，不能误当代理真实测试目标。[S1]

复用URL不等于复用测量语义。已有观测结果只能标明来源、时间和是否新鲜，不能用户按了“立即测试”就把一分钟前结果当新测试。

固定v26.9.9的ObservatoryService提供GetOutboundStatus读取结果，未提供可凭空假设的立即Probe RPC。[S2] 不修改probeInterval或重启生产核心来伪装手动测试。

### 9.3 隔离测试实例，不能切换用户正在用的节点

采用v2rayN使用独立测试配置/进程的思路，而不是复制其多核心体系。[S3]

- 仍只运行一个生产核心，但允许Server临时拥有一个受控测试核心。
- 按小批次创建临时多文件confdir和若干loopback代理入口；每个入口固定路由到被测节点，复用现有Codec/Writer/Process。
- 仅测试所选节点，不向测试配置复制生产TUN、任意监听、后台Geodata更新或全量原生路由。
- 测试请求明确走对应本地代理入口，禁止直连fallback造成假阳性。
- 保留必要传输/TLS/REALITY/资源设置；无法隔离表达的特殊原生节点说明原因，不把配置偷偷简化后报告通过。
- 测试完或取消后回收测试进程、端口和文件；不动生产PID、选择、模块、来源和运行文件。
- bounded concurrency、timeout、取消、进度和逐节点结果；不要每1000个节点同时启动1000个核心。
- Group的URL test测试其策略当前选路；ICMP/TCP对组无单一端点，提供“测试成员”或不适用，不生成假组IP。

Config → Tests保存默认目标、超时、并发与下载上限。允许内置公开连通性测试URL作为可编辑默认；它是第三方服务，不冒称XRM自建。普通自动测试一律用loopback fixture，不请求用户全部机场。用户明确点测试或授权时才执行真实节点探测。

## 10. Geodata：共享资源管理 + Profile选择

把Geodata做成可下载、查看、更新的共享资源，不只提供geodata模块原文编辑。

入口：Config → Geodata（共享资源管理）；Profiles选择资产包；Modules → routing/geodata显示引用与原生效果。继续七个顶层页。

资源记录包括：名称、GeoIP/GeoSite类型、来源URL/本地文件、目标文件名、当前版本/更新时间、最近结果、使用它的Profile。管理元信息存现有数据库，二进制.dat在资源目录，不塞SQLite文本字段或原生JSON。

- 支持添加、下载、手动更新、可选定时更新、查看引用和删除未用资源。
- 下载复用HTTP/操作进度/通知；先写staging并检查，再替换管理器资源版本；失败保留last-good。
- 不用“下载得到200”当作.dat有效。检查内容、实际格式及预设所需标签，可借助固定核心在隔离配置中确认；没有足够证据不要虚称标签均存在。
- GeoIP与GeoSite的.dat含义不同，不能按扩展名互换。不同提供者相同tag不必相同含义，UI和预设明确所需来源/标签。
- Profile选择的geoip.dat、geosite.dat及额外命名文件落到本轮资源上下文，保持RunSpec的正确资源路径；不能误用原生env去代替启动前资产路径。
- 全局资源缓存更新默认不改正在运行的文件，显示“新版本可应用”；显式Apply/Connect才绑定新版。旧实例所需资源按快照持有。
- 不写/usr/share中包管理器维护的资产，不因为换Geodata丢掉原Profile需要的证书等其他资源。

### 同一个物理文件只有一个更新者

Xray原生geodata支持定时下载/重载，并要求相应资源文件先存在。[S4] 不能与管理器定时器竞争同一个文件。

默认模式：XRM更新共享缓存，Profile在Apply时使用选定版本。
高级原生更新模式：明确生成/保留用户的geodata配置，让核心更新这个运行/方案专属资源副本；XRM不再定时写该副本。共享缓存不因此被所有运行核心同时修改。

核心原生更新模式是否真实完成热重载，按目标版本测试。不能将“缓存更新”显示为“运行规则已更新”。不建设两套资产同步引擎或通用分布式版本库。

## 11. Profile模板：Desktop / TUN / Custom

新建Profile的第一步选择模板卡片，显示用途、会创建/启用哪些模块、本地入口与系统影响。模板和后面的“流量怎么分流”是两种独立选择，不能混成一个巨大的开关。

- Desktop：应用显式使用本地SOCKS/HTTP入口；基础模块可运行，统计配置可见；不自动改系统代理。
- TUN：使用目标Xray原生TUN能力，不引入sing-box或tun2socks；显示设备/地址/MTU/路由与权限，避免核心出站回环。模板创建本身不改系统网络，用户明确启动后核心按配置执行。
- Custom：保留完整模块目录与说明，启用项由用户决定，不强塞Desktop入站；支持从现有原生配置导入所选模块。

Xray TUN文档的部分设置具有平台限制，例如dns项只对Windows生效；不能写到Linux模板就声称已配置宿主DNS。[S5] 逐项核对当前固定核心的TUN路由、接口选择与清理行为；不为了模板运行擅自执行宿主nftables、sudo或修改现有网络服务。

开发验证TUN时可在已有隔离环境进行；没有可用权限/环境就明确标记未做流量验证，不能以-test冒充接管成功，也不为此顺手建立VM平台。

模板是一次性创建来源；已有Profile不会因模板更新被覆盖。15个模块都可查看样例，不要求全部输出。开启需要资产的预设时先下载/选择资源，没有资源不能输出看似有效的空引用。

## 12. 分流预设：参考v2rayN，结果落到原生JSON

这项明确授权实现，不是只给一个外部URL让用户自己粘贴。

先读取v2rayN实际实现：ConfigHandler.InitBuiltinRouting及Sample/custom_routing_white、custom_routing_black、custom_routing_global。[S6] 阅读它配套的数据来源与必要DNS设置，而不只抄几行规则。[S7]

首批至少提供：
- v2rayN风格绕过大陆（Whitelist）；
- v2rayN风格黑名单代理（Blacklist）；
- v2rayN风格全局（Global）；
- 简单全直连；
- 自定义原生规则。

显示中文说明、默认出口、哪些范围直连/代理/阻断、依赖哪些.dat及标签。

不能用名字猜行为：所参考Global样例仍含局域网直连和UDP443处理；white有Google等例外；black有自己的最终直连。保留或修改这些行为都要明确说明。测试确定改写前后行为，不把这些名字当数学上“全局”的保证。

“复刻”是复现明确分流行为，不复制v2rayN的全部内部数据模型。若复制其代码或规则文件，记录具体版本和来源并处理原许可/归属；不要擅自更改XRM的许可证或假称内容原创。[S8]

### 选择预设的操作

Profiles中选择分流预设，也能从Modules → routing进入同一入口：

```text
选择预设及Geodata包
→ 展示用途和依赖
→ 生成plan，列出实际变更文件与JSON diff
→ 用户确认保存
→ Modules马上能查看这些原生修改
→ 显式Apply/Connect才影响运行
```

- routing规则保存到现有routing模块；必要DNS等修改分别保存所属模块。
- 不生成顶层rules/preset等伪原生键；不把全部配置合成单文件。
- v2rayN中的remarks/enabled等管理字段按来源语义处理，不盲目写成核心字段。
- 预设里的proxy动作必须接到Profile当前的Node/Group目标：使用已有Target/绑定机制，最终是正确outboundTag/balancerTag；不能留下不存在的proxy出口，也不能复制成嵌套group。
- 目标还没选时可以保存“待完成目标绑定”的可见状态，不伪造UUID；缺少必要目标时阻止连接并引导选择。管理绑定不混入原生模块正文。
- 选择预设是明确替换/设置routing.rules，不偷偷覆盖原有balancers、管理API规则或用户未知字段。已自定义内容先展示diff，默认不是再次append一套相同规则。
- 多次选择同一未改动预设应幂等；后续手工编辑标为“基于该预设的自定义”，不在每次render时用模板覆盖用户修改。
- 预设只提供初始化/显式应用，不成为数据库中的第二份完整可写routing。
- 默认目标变化时，通过明确已有绑定或可见的局部修改更新对应目标；不能让旧proxy绑定悄悄覆盖用户新手写目标。

GeoSite/GeoIP/ext引用的文件、类型与tag必须对应。[S9] 缺少预设所需标签就提示资源不匹配，不跳过该规则后宣称预设生效。规则顺序保留；域名分流所需嗅探/DNS行为按官方文档说明，不把仅有IP流量当成总有可用域名。

## 13. 实现分工与最小接口边界

允许新增少量职责明确的实现，不为每个对象配一套Service/Repository/Factory：

| 部分 | 责任 | 不应拥有 |
|---|---|---|
| AppShell / FocusScope | 三段布局、两层导航与事件路由 | 数据库与代理决策 |
| TableView / NotifyOverlay / TrafficChart | 可复用呈现、viewport、消息与短序列 | 每帧RPC、各自独立采样器 |
| ModuleEditor | 同一草稿的结构编辑/JSON/外部编辑 | 另一份持久模块或全schema平台 |
| Inventory reconciliation | 当前节点去重/删除、说明提取、引用结果 | 直接重启核心 |
| Runtime snapshot | 已运行参数与资源的有限所有权 | 永久历史节点库 |
| NodeTestService | ICMP/TCP/独立代理测试任务 | 修改生产选择、自动下载全部节点流量 |
| GeodataService | 资源下载/更新/引用元信息 | 与核心争抢同一个资产文件 |
| Preset/Template functions | 当前输入→改动计划→原生模块保存 | 每次启动重建用户手写配置 |

界面聚合和组件复用不是新架构层。CLI新增测试、资源、预设操作按已有命名规范提供，名称/ID的解析沿用既有实现。Manager/Server边界不变。

## 15. 必须从真实终端观察的验收

下面是开发者自己通过PTY/终端工具必须完成的流程，不要再次把基础问题全部交给用户发现。自动操作不冒充用户本人，但同样必须看当前画面、读真实状态、产生实际流量。

### UI与布局

- Tab到Nodes→Enter→Tab切来源→Enter进表→滚动→Esc回二级→Esc回顶级；输入f/s/c/q不触发后台快捷键。
- 同一操作同时用键盘、已有鼠标入口完成，焦点与选中一致。
- 80×24、120×35、160×45、200×55分别采集当前屏幕。表头/数据列边界一致；宽屏有明确布局，不在左上角堆文本。
- 拖小到70×20再放大：只有尺寸提示，草稿/选择/后台连接不丢失。超长二级Tab也可找到当前项。
- 右上角通知更新一次操作，完成后自动消失，弹窗/列表不被抢焦点，底部帮助不被旧成功消息挤掉。
- 1205节点End/Home/PageDown、过滤和刷新都保持高亮可见，无假1000上限。

### 库存与快照

- 同一来源包含连接等价重复、真实不同端点和额度说明；连续10次刷新不增长、不丢不同连接，说明不进入可连接列表。
- 当前A正在实际转发时，成功订阅更新移除A：DB当前节点查不到A，All也不显示A，但现有代理仍能返回A的marker；Overview正确说明运行来自旧快照。
- 切到B成功后，旧实例退出且无实际引用的数据释放；在切换失败/取消中仍能安全保留或恢复A。
- 自动恢复当前核心与Server正常重启路径有实际覆盖；不因删除库存就读取空节点或重新复活历史。
- 下载失败/部分解析失败不批量删除；Local不受影响；不存在永久历史soft-delete来假装完成。

### 原生编辑与模板

- 进入Modules直接切dns/policy/routing等二级Tab；无source且disabled不崩。
- 从结构界面增删DNS server/hosts、排序规则、改bool/number/array；JSON立即反映；高级未知字段不丢。
- 切原文/外部编辑/结构再保存，只有对应模块变；保存不重启；preset的diff准确。
- Desktop真实本地代理，Custom保持自定义，TUN按环境标明真实或仅配置验证，不运行用户宿主TUN做普通CI。

### 测试与分流

- ICMP/TCP/URL test各有独立状态与失败语义；错误认证节点TCP可通而Real test失败，不能假报代理成功。
- 运行生产核心时测试另一个节点，生产PID/选择/FileSet不变；取消回收测试核心；观测结果复用注明时间。
- 流量图来自真实传输采样；间隔/缺失/重启处理正确，不用随机曲线填充。
- 本机资源服务提供真正有效、包含合成标签的.dat，下载/失败/更新/绑定可验；不能用任意空文件加-test冒充Geo规则有效。
- 应用三种分流预设后，通过固定核心与可区分loopback出口证明命中顺序、direct/proxy/block目标。断言实际流量及结果，不只检查JSON里有geoip字样。
- 更换一个Profile的资产/预设不污染另一Profile；输出仍然是原生多文件，可导出独立运行。

真实测试不能只看终端输出历史中“曾经出现字符串”；检查当前终端网格/样式、进程行为和网络结果。有截图工具时实际查看截图再调整排版。

- **S3 v2rayN测速实现：** TCP连接探测与通过测试核心/本地代理入口访问URL分离。
- **S4 Geodata：** 定时下载/重载与已有资源文件约束；和管理器缓存分工。
- **S5 TUN：** 原生TUN的平台、自动路由、出站接口和DNS平台限制。
- **S6 v2rayN预设：** 实际初始化逻辑和white/black/global规则。
- **S7 资源来源：** v2rayN Global.cs与Loyalsoldier项目；默认值可能变化，实施时固定快照。
- **S8 许可：** 引用或复制时保留对应项目要求的许可/归属，不能只复制内容不记来源。
- **S9 原生routing：** geoip/geosite/ext、rule顺序与balancer归属。
- **S10 视觉参考：** Clash Verge Rev官方深色预览（已可查看）；xrat布局源码（其GIF不可读取时不声称看过动画）；v2rayN UI文档。
- **S11 FTXUI：** 当前项目锁定版的table、graph、tab、终端尺寸接口。示例只演示机制，不照抄示例无限动画循环进产品。
