## Changes within the RC exception

- E2E-07's failing assertion was a **TEST-DRIVER-BUG**: retained `stats` selection meant its helper edited `stats` but compared `api`. The corrected driver reads the actual module index, selects `api`, and verifies the displayed object. It now seeds a compact native API Source, then checks exact ASCII-space preservation, parsed semantic equality, unknown fields and native types, array order, disk bytes, inclusion, and unchanged running state.
- The investigation separately proved a **PRODUCT-BUG** in the same edit path. Opening a valid JSON Source used to replace its bytes with `Json::dump(2)` before the user changed anything. `src/tui/pages/modules.cpp` now keeps the original Source text in the JSON draft; Visual edits retain their established behavior. The explicit text-preservation contract is cited in [the investigation](g5-rc-e2e07-investigation.md).
- The user's Nodes / Content / Enter report was reproduced. `src/tui/shell/workspace.cpp` now opens the existing read-only Details dialog for a selected node. The isolated [before](evidence/g5-rc/nodes-enter-before/after-enter-80x24.txt) and [after](evidence/g5-rc/nodes-enter-after/after-enter-80x24.txt) screens and [fixture trace](evidence/g5-rc/nodes-enter-after/trace.json) show Enter and Esc behavior without runtime change. Two older UI tests were adjusted to close the now-functional detail dialog before issuing their subsequent keys. Group Enter behavior was not changed.
- The user's Config / Core / Content / Enter report was reproduced on an isolated registered core. `view_detail()` previously assembled the core detail text but never displayed it; it now opens the existing read-only Details dialog for a selected registered core. [Before](evidence/g5-rc/core-enter-before/after-enter-80x24.txt), [after](evidence/g5-rc/core-enter-after/after-enter-80x24.txt), [after Esc](evidence/g5-rc/core-enter-after/after-esc-80x24.txt), and the [fixture trace](evidence/g5-rc/core-enter-after/trace.json) record the actual 80×24 behavior and unchanged runtime. The existing UI-04 test now covers this Enter/Esc path; no Core action or running-state semantics changed.
