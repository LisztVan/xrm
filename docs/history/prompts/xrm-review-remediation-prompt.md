**本轮是有证据的系统性修复，不是第三次推倒重写，不是重新审计后停工，也不是追求一个更高的评审分数。** 保留已经成立的领域模型和组件基础，优先修公共组件、布局规则、动作呈现与输出适配，使所有使用这些基础的页面共同改善。允许实质性重做有缺陷的组件和页面布局，不以最小代码差异为目标；但不得借机改后端架构、发明新产品或堆功能。

| 评审内容 | 本轮处理方式 |

状态使用明确词汇，例如：`待验证 / 已复现 / 已修复 / 当前已修复并补证据 / 未复现 / 环境受阻 / 设计建议不采纳 / 非同一语义需区分`。未经复现的风险不写成已确认缺陷；“未复现”必须说明检查范围，不等于证明不存在。

## 3. 不允许在修复时回退的产品约束

1. 保留 TopNav / SecondaryNav / Content 的焦点模型。Tab/Shift-Tab 只在所属层内切换；表单内部切字段属于局部控件焦点，不跳到顶层。导航 Enter 只进入一层并消费，Esc 只关闭/返回一层。
2. 不恢复数字键、`[]` 或方向键跨顶层/二级导航的另一套路线。内容列表、树、输入、Help 内的方向键属于局部操作。
3. Cursor/高亮、View、Use、Edit、Draft、Saved、Running 不得合并。View 不写入；Use 可取消；取消 Use 不停止核心；Edit 是指定 Profile 的 Modules 写入模式，不是 Profile 元数据编辑器。
4. Edit 关闭时模块写入口均只读；Profile 本身的创建、重命名、复制、删除不受模块 Edit 开关限制。Use/Edit 切换不自动连接，保存不自动应用或重启，退出 TUI 不停止核心。
5. Modules 保持全宽单工作区，Visual/JSON 共用草稿、F2 切换。未知字段、原生类型、数组顺序和保存边界保持，不新增第二套配置权威来源。
6. 用户已经要求：**主体不要混入对象说明和快捷键长条；对象详情、路径、上下文和状态归底部；完整操作集中到 Help；短时结果在右上角 Toast。** 本轮继续遵守。
7. 所以不直接采纳“每页常驻 2–4 个动作”“右侧动作/Inspection 面板”等建议。通过更可发现、可操作的上下文 Help 和清楚的底部信息解决同一问题。若你认为必须改变这个约束，单独提出冲突，不偷改；不影响其他修复继续完成。
8. 业务标签、表单字段和就地校验属于任务内容，可在主体/表单出现；这里禁止的是把全局状态、长说明、系统诊断和帮助再次混入业务数据，不是禁止必要标签。
9. 保留状态诚实：进程运行不等于流量已验证；数据未知不等于零；只保存不等于正在运行。不要为让 Overview 更饱满而自动开启统计、API、Metrics 或生成假指标。

## 5. R1：导航、底部详情与通用截断

### 5.1 二级导航

- 使用项目实际注册的 15 个原生模块，不根据报告举例新增或删除根键。
- 继续在 SecondaryNav 用 Tab/Shift-Tab 切换。任何支持尺寸下，当前项完整可辨，离开视口时自动滚动进入视口。
- 发生溢出必须有明确标志和位置，例如左/右续项标识以及“第 11/15 项”；这些数字只是状态，不成为数字快捷键。
- 不把半截 `pol`、`bur` 当作正常标签结束。必要时导航名称采用清楚省略，底部提供完整原生 key。
- 窄屏保留一条清晰、可滚动、带溢出提示的导航；宽屏可多行，但不能因此改变遍历顺序、焦点层级或让布局在每次按键时跳动。
- Nodes 的范围（全部、本地、Groups）与订阅来源必须有分组标签/分隔，来源名与 Local 同名时仍能分辨。保持一个二级选择模型，不临时发明第三套导航。
- 选中导航项与模块 included 状态使用不同表达；included 不只靠颜色，更不能与当前焦点混用一种标记。

### 5.2 底部详情

- 把窄屏直接消失、宽屏漂移到右侧的对象详情统一收回底部上下文区域。优先复用一个底部详情组件，而不是给每页另造一栏。
- 80×24 常驻保留身份、关键状态和必要路径摘要。更多详情可以通过 Enter/View 或 Help 中已声明的详情动作在同一底部区域展开，或进入只读详情层；不能因宽度小而丢失访问入口。
- 宽屏可以在同一底部区域多列排真实关联信息，主体增加有用表格列和可视行，不恢复与用户要求冲突的右侧 Inspection。
- 高亮 B、View A 时，详情必须写清属于 A 还是 B，不把移光标当成 View，也不把 View 当 Use。所有异步结果绑定稳定对象 ID。
- 80×24 下底部有预算上限和收缩规则，不能反过来把主表/表单挤成不可用的一两行。局部详情展开和返回不能丢失主视图滚动/焦点。

### 5.3 截断

- 路径、来源名、模块名、子系统名采用一致且有可见省略标记的策略，不输出看似完整却错误的路径。
- 完整值有明确可达的只读详情；实际操作始终用完整原始值，不使用显示用字符串。
- CLI 的机器输出、可复制命令、必须引用的 ID/路径不被视觉裁剪。
- Unicode 截断依据终端显示宽度，不能切坏 UTF-8 或将正常中文换成问号。

## 6. R2：不恢复快捷键长条，重做 Help 的任务入口

### 6.1 唯一入口与执行模型

- 把现有固定 Help 入口做清楚，例如 `F1 帮助与操作`（产品语言统一后选用对应文案）；非文本上下文保留 `?` 别名，输入控件中的 `?` 必须是文字。底部只保留这个轻量入口，不追加十几个快捷键。
- **本轮允许将现有 Help 改为可操作的上下文帮助菜单**，这是表现层修复，不新增一套动作语义。按一次 F1 只打开 Help，绝不顺手执行动作。
- Help 内先显示当前任务和对象，再显示优先操作、其余当前合法操作、必要导航/输入说明。列表可用方向键选择、Enter 显式执行、Esc 关闭并恢复原焦点。
- Help 的执行、快捷键、启用条件、目标、后果和禁用原因必须来自同一个动作定义。需要表单/确认的动作仍进入原表单/确认，不能从 Help 绕过安全边界。
- Help 触发动作后关闭或转换当前局部层，消耗该次 Enter，不穿透到新表单的默认按钮，不重复执行。
- 将不能执行但用户需要理解的前置条件放在说明区，例如“当前只读，需要在 Profiles 为 Alpha 开启模块 Edit”；不是伪装成可执行动作，也不是把所有禁用项无差别塞进列表。

### 6.2 具体内容必须解决的任务

- Overview：Help 首部能发现针对哪个已保存目标连接、如何停止、统计当前为什么不可用；只给实际存在且适用的操作，不虚构一键修复。
- Modules：说明为什么只读、去哪里启用 Edit、当前 Source/Runtime、子表单提交到稿件和模块保存的区别，不能只写“F2 切换”。
- Profiles：Use 与 Cancel Use、开启/关闭模块 Edit 使用状态相关名称，并说明不改变运行核心。
- Form/Collection：当前在编辑哪个对象、字段属于哪里、提交写到哪一级草稿、取消会丢哪些局部修改。
- Logs：暂停/跟随、查看原文、当前位置和缓存状态的含义；不出现任何核心运行操作。
- 通知历史：明确入口和未读/合并数量含义，不能只显示 `more in history`。

### 6.3 快捷键收口

同一动作多个合法别名合并为一项，例如 `Ctrl-S / s`，不是两个 Save。不要为了“统一”让 s 在文本框里不能输入。

大小写键不应成为用户发现功能的唯一途径。本轮优先通过 Help 可选动作解决，不随意改完所有快捷键再造成一次学习成本。同一个上下文有真实冲突才按契约调整；不同页面的同字母不自动算错误。

切换类操作显示下一步实际动作，例如 Include 或 Exclude，而非一直显示 `Include / exclude`。Help 文字、触发条件和真正行为一致。

## 7. R3：给公共输入和表单补齐产品规格

### 7.1 空输入与字段结构

- TextInput/TextArea 在“为空且未聚焦”时也有可辨认的输入区域、边界或 surface；只读文本、禁用字段、空输入外观不混同。
- placeholder 不是实际值，不写入数据；字段标签始终可见，聚焦不导致所有行重新排版。
- 每个 Field 统一包含 label、必要/可选说明、control、简短说明、validation。错误属于哪个字段必须一眼清楚，不能出现孤立 summary 像前一字段残影。
- Select 的折叠/展开可辨识、位置稳定；不聚焦时仍能看出这是可选择的值。
- 通用字体强调、间距、背景、焦点样式统一经过主题 token；不要针对 DNS/Group 分别补魔法空格。

### 7.2 可选原生字段

不要照抄评审中的“未设置/默认/自定义”三态套所有类型。先明确真实数据状态，再使用最少的控件表达：

- 可选布尔：一个选择器表达“未设置，使用核心行为 / 显式 true / 显式 false”，分别映射字段不存在、true、false。
- 可选枚举：未设置 + 官方允许值；已有未知值保留并清楚说明，不能打开表单就替换。
- 可选数值/文本：未设置/显式值的清楚模式，配合一个真正输入框；未设置不能与 `0`、空字符串或 false 混同。
- 不用 `[ ] Explicit + Use default + not set` 三件套表达一个值；也不能简化时丢失 absent/false/0 的区别。
- 显示“默认”只表示不写字段，除非已经从适用官方文档确认实际默认值，否则不在文案中编出数值/行为。

### 7.3 集合与草稿

- CollectionEditor 根据集合语义使用标题和输入标签：域名、地址、服务器、规则不是永远都叫 Entries/Value。
- 空集合显示真正可输入的新条目区及 Add；没有选中项时 Update/Delete/Up/Down 不装作可执行，有序集合在合法位置才允许重排。
- 对象集合打开完整多字段表单；字符串集合使用轻量行编辑。仍共用集合状态/校验机制，不恢复逐字段问答链。
- 选中条目、编辑条目、待新增条目有明确身份；刷新和重排不能把修改写到错误索引。
- Add/Update 仅提交父稿，模块 Save 才持久化 Source，Connect/Apply 才影响运行。帮助及确认在操作前解释这些边界，而不只在事后 Toast 解释。
- 字段无效、RPC 拒绝、断连、切换模式失败，都保留值、焦点和草稿。有未保存修改的对话框写明对象、修改范围，以及 Save/Discard/Continue 的真实后果。

## 8. R4：统一浮层与主题的整屏合成

### 8.1 Dialog

- 由一个层负责边框、标题、背景、padding 和定位。内嵌 Form/Confirm 不再重复画外框。
- 普通 Dialog 在可用内容区居中；大表单可用受控全宽/近全屏布局，但应显然是局部模态，不和背景列表同权。
- 用主题化遮罩或降低背景强调表达模态；不是硬编码一个让 Paper 失效的深色覆盖。
- 焦点陷阱、Esc 一层返回、关闭恢复原对象与焦点同时成立。不得仅修边框而不验证输入归属。

### 8.2 Toast

- 保留右上角、自动消失、重复合并、有界队列/历史，以及“改了什么、运行是否变化”的既有反馈结构。
- 每个 Toast 完整绘制自己矩形内所有单元格和背景，不让分隔线/表格/JSON 穿透。消失、移动、队列变化和 resize 后必须正确重绘原区域。
- 不抢焦点、不推开布局、不阻塞按键。定义与 Dialog/Help 的 z-order；不得遮住当前正在输入的字段或关键错误。必要时排队或在允许区域布置，但不能无声过期一条用户从未能看到的错误。
- 重复次数和待查看数量使用带含义的文案，不单独留下 `(2)`；历史入口来自现有 Help。
- 保留已经成立的通知计时行为，使用可控测试时钟验证，不为了截图另造一套时序。

### 8.3 主题

- 优先真正修完 Paper，而不是删掉一个正式提供的功能来让测试通过。若确实不能支持，明确列为未完成及迁移方案，不自行宣布通过。
- 主题覆盖整张画布、空白 cell、表格、滚动区、底部、Dialog、Toast、输入、Help、resize 新增区域和恢复后的背景。
- 提升列头和必要元信息的可读性，不把承担识别功能的文字过度 dim。
- 验证当前提供的深色、Paper、16/256/truecolor、NO_COLOR 及已有终端降级模式；不把“有主题截图”写成“所有主题全页验证”。

## 9. R5：任务信息、状态与用户语言

### 9.1 七页需要不同的任务组合，不是同一张表复印七次

- Overview：把实际运行、已保存方案/目标、可确认的观测结果组织成清楚分组；没有统计时解释原因，并在 Help 给出真实下一步。不要自动开统计，也不要编造历史曲线。
- Profiles：主体便于比较方案；底部显示 View 对象的核心、已保存目标、来源和模块摘要中真正有用的内容，而非原样重复三列表格。
- Modules：主区是领域编辑器/只读查看；树、集合、表单的空间按实际数据分配，底部解释编辑模式、来源、草稿和保存层级。
- Subscriptions：展示更新结果与当前节点、绑定作用范围；详情区区分上次尝试/上次成功及真实失败原因，不展示带凭据的 URL 摘要。
- Nodes/Groups：分别看清当前浏览对象、已保存目标和实际运行目标；来源、启用、支持程度、测试结果分别有明确含义。
- Logs：保留消息阅读优先的专用布局，不塞进通用表格+Inspection 模板。
- Config：按设置类别使用合适表单/列表；版本/厂商原始字符串属于高级详情，不占据普通操作所需的信息位置。

不要为了提高屏幕占用率填充空白。使用足量且有代表性的测试数据；数据只有一条时适量留白是合理的。宽屏的改进是可读列、上下文和可见记录增加，不是虚构信息、卡片堆叠或打破 Modules 全宽规则。

### 9.2 状态呈现与作用域

- 将 `Use Edit Run`、`Saved Run` 的散装 token 串换成固定位置、明确标签的表达。宽屏可用独立列，窄屏用清楚摘要与底部详情；不能只靠颜色。
- 使用统一的用户词汇表，明确每个词对应的数据字段、作用域和未知态。`CURSOR` 不再同时表示日志传输位置、表格高亮和面板标题。
- 草稿/未保存修改统一叫法；修正单复数、无含义的大写标签、重复状态、冗余零值和 Help 对齐。
- Use/Cancel Use、开启/关闭 Edit 给出与保存动作一致的轻量反馈，写清目标及运行未变；不因为纯移动光标就弹通知。

### 9.3 不可把评审中的“术语统一”误实现成数据合并

- 节点 enabled、supported/raw-only、available、测试结果可能是不同维度。查实际合同后命名，不把不同字段统一成一个“正常”。
- 模块 inclusion 是管理器是否组装该源文件，不等于虚构原生对象有 enabled 字段。
- CLI `select node/group` 与 TUI Profile `Use` 不是同一动作，不能为了同词硬改含义。
- Use/Edit 是 TUI 会话状态。不能为了在 `xrm profile list` 显示它们，创建全局持久状态、猜测别的会话或改 xrmd 模型。CLI 展示后端确认的已保存/运行事实；会话态保持其作用域。

### 9.4 离线与错误

- 底部用清晰的连接状态/缓存标识、最后成功信息和恢复途径区分实时、旧缓存、加载失败和真正空数据。遵守信息归底部，不把错误冒充日志记录。
- 断开时可以保留数据，但不继续无说明地显示为 LIVE/FOLLOW 正常获取；恢复后清楚标识，不自动重放写入，不抢焦点。
- 建立共享的用户消息适配层，按操作、对象、原因、恢复建议表达错误。TUI/CLI 使用一致术语，但各自排版。
- 缺少 socket 只能说明该端点不可达，不能未经查询就断言 daemon 一定没启动。建议检查实际端点和已实现命令；不要生成未经核验的 systemctl 指令。
- 默认人读界面不以 `module.form`、`connection.connect` 等内部 RPC 名为错误标题；必要技术原因在可展开诊断/现有 verbose 渠道保留，不能为了“友好”丢掉 errno、未知错误详情或故障定位信息。

## 10. R6：日志先弄清身份，再改文字

两份评审对 Logs 整体质量不同，但都指出 CURSOR、稀疏时间、子系统裁剪等问题。**不得仅把 CURSOR 改成“记录号”，就把 IPC chunk ID 冒充独立日志记录 ID。**

先确认现有数据流程：读取游标/IPC chunk → 逻辑记录或保真文本单元 → 视觉换行。检查一个 chunk 多记录、一个记录跨 chunk、原始多行、UI 自动折行如何区分。

- 保留当前已经正确的级别、消息优先级和续行对齐，不重写无问题的日志服务协议。
- 传输游标放技术详情，不作为普通用户的“日志序号”。如显示本地阅读编号，说明其只对当前缓冲/会话有效，保证刷新、暂停和恢复期间足以稳定定位；不能宣称为服务端全局 ID。
- 无法可靠拆出结构时，以原文保真展示，不编造时间、级别、子系统或记录边界。时间未提供不能拿采样时间填充。
- 视觉续行有缩进/引导，明确不同于新记录；跨 chunk 的 UTF-8 和行尾需正确处理。
- 长子系统名采用可辨省略或详情展开，不能用看似完整的半截值；80/120 列的降级保持阅读和完整原文可达。
- 布尔 dropped/truncated 只能表达有/无或未知；只有后端真实提供数量时才显示具体丢弃数，不能把 false 改成 0 后就宣称具有计数能力。
- FOLLOW/PAUSED、未读新增、缓存/断开、保留范围用用户可理解的词放底部。去掉没有操作意义的 `cursor 33` 调试信息。
- 原始输出包含控制字符/ANSI/OSC 时安全显示，不让日志内容控制终端、伪造 UI；保留可审计原始数据，不执行其中控制序列。
- 保持已有缓冲上限和长日志性能，不为修编号引入新的无界内存。

## 11. R7：核实模块表单深度，修真缺口

### 11.1 逐模块覆盖

逐个检查当前实际注册的原生模块，更新 `docs/module-form-coverage.md`，每项写清：领域区段、查看/新增/修改/删除/适用的排序、可选字段、未知字段、只读入口、高级 JSON 边界、真实运行证据。

**不要把报告里 Config 的 Tests 页当成 Xray 原生顶层 tests 模块。** 根键和字段以项目当前支持版本及 Xray 官方文档为准。

对只有占位标题的页面，补清楚它是什么、源是否存在、是否 included、为何只读，以及当前支持的操作。对正常任务确需领域表单的有限结构，复用组件补齐，不以“高级 JSON”掩盖承诺过却未实现的基本能力。合理保留高级 JSON 入口，但边界必须在 Help/底部可见。

只报告真正检测到的未覆盖字段/路径；不能编造“还有 N 个字段”，不能用整个对象字段数冒充高级字段数量。敏感值不出现在摘要里。

### 11.2 DNS/routing 等已有深表单

- 核验 `Rule label *` 是否被前端强制必填，并核对当前适用的官方文档。若原生 ruleTag 可省略，不强迫用户编名字；未命名规则可用仅供显示的摘要/序位，不写入伪造原生值。
- 不为了补标签在配置中引入便利字段，不改变数组顺序。
- routing 表单在首屏就能理解“匹配条件 → 目标”的结构。目标字段在滚动下方时要有组名、剩余内容提示和可达路径，不根据旧截图直接断言字段不存在。
- 枚举/互斥目标、DNS 可选值、字段默认和限制均先核对官方相关文档；不凭模型记忆编 schema。必要入口：`https://xtls.github.io/llms-full.txt`。访问不到或文档未提及则记录，保留高级编辑，不猜字段。
- Visual→JSON→Visual 不丢未知字段、false/0/空集合、数组顺序；取消、失败和保存不改变无关字段和运行文件。

## 12. R8：CLI 修用户语言，保护机器契约

保留已经做好的分组帮助、裸分组显示本层帮助、help 不访问 daemon、TTY/管道分流、显式 socket/Profile ref、可引用 ID、JSON、stderr 与退出码。

### 12.1 错误与回执

- 默认人读错误标题使用用户实际输入的命令/任务和对象，不使用 RPC 方法名。
- 以当前产品语言统一受控文案；当前英文界面先统一英文，不在本轮引入整套 i18n 框架。远端原文和 OS 技术细节可以在明确标注的诊断区保留，不能把未知错误翻译为一个错误原因。
- 缺核心、对象不存在、socket 错误、保存失败各有对应的恢复建议。示例命令必须来自当前真实 help，并保留目标和测试 socket；没有必要参数时不能冒充直接可执行。
- 成功回执优先给名称和可引用 ID，核心是否运行、流量是否验证分别表达。读不到附加名称时标为未知/只显示 ID，不把已成功的操作改报失败。
- 人读 `null` 按作用域解释为未设置、尚无运行目标、数据不可用等，不能一律替换成 none 或零。

### 12.2 帮助与重复信息

- 参数 metavar 使用真正有意义的 NAME、PROFILE、MODULE、PATH 等展示，不改变实际参数名/解析语法。
- `source/runtime` 取值和默认清楚展示，不泄漏 validator 的拼接语法；移除 `(avoids conflict with top-level commands)` 等实现理由。
- 根级通用说明放根帮助，叶级只保留相关上下文和下一层指引，避免每页复制五行尾注；直接打开叶帮助仍应足以完成该操作。
- `config modules` 明确区分源路径与运行文件来源，合并无意义重复，但不把两个不同对象当成重复删掉。来源不存在时诚实说明。
- 清理空行、复数和标签噪声，不因人读排版改坏已承诺 TSV/机器输出。

### 12.3 兼容性

- 原有 JSON 字段、类型、错误 code、输出流、退出码及 watch 逐条记录协议继续保护。不要为了让 JSON 看起来“友好”删除内部 code 或加人读提示。
- 结构化 message 的文案变更需核对现有承诺和依赖；可调整自然语言时统一受控描述，但不静默改变已承诺机器接口。若存在冲突，在记录中明确说明，不能声称已兼容而跳过测试。
- 非 TTY 无 ANSI/浮层/交互等待；stdout 结果、stderr 诊断各自正确。保留此前修好的 watch 刷新、断连错误与 SIGPIPE 行为。
- 不通过全局持久化 TUI Use/Edit 来“补齐 CLI 状态”。这是领域边界，不是 CLI 缺陷。

## 14. 执行顺序

### 阶段 A：短基线与决策

读取输入，构建当前工作树，复现最有共识的问题及影响分级的疑点，建立追踪矩阵。更新唯一交互/视觉规范：尤其 Help 可操作化、底部详情、二级导航溢出、可选字段、浮层背景。只形成一套确定实现，不写多套方案让用户挑颜色。

### 阶段 B：公共机制

先修 Field/Form/CollectionEditor、Dialog/Toast、主题整屏背景、导航/底部详情、动作 Help、消息适配等公共层，做组件与整屏合成测试。不要先给七页分别加特判。

### 阶段 C：七页、模块、日志与 CLI 接入

让生产页面实际复用修复后的组件。完成模块覆盖核实与真实缺口，修日志数据身份/排版和 CLI 用户输出。移除被替代的并行处理分支，不能新 Help 与旧执行系统各自发明条件。

### 阶段 D：操作、观察、纠正

用当前构建实际运行 V01–V15；看整屏，不只搜文字。发现公共根因时回组件修，再验所有受影响页面。执行所有相关回归及项目规定的全量/真实核心验收，未运行项目与原因明确列出。

持续推进到实际实现与验证完成，不在更新文档、列出问题、组件 Demo 或第一轮截图处结束。真实阻碍可记录，但不能以“还需人工 G5”为理由跳过自己能完成的工程/终端检查。

## 15. 交付与完成定义

交付实际代码和回归测试，更新唯一规范、模块覆盖文档与人工验收清单。另保留一份集中记录（建议 `docs/design-review-remediation.md`，若已有同责文件则更新它）和同轮证据目录，不散落十份重复总结。

集中记录包含：

1. A/B 全部条目的去重映射、复现判断与处理状态。原分级和当前分级分列，采纳/不采纳建议有理由。
2. 每个根因修了哪些公共组件、哪些生产页面实际使用；没有通过组件复用的特例须解释。
3. 当前构建身份、完整测试命令、通过/失败/受阻/未运行；不得只报断言数量。
4. 80/120/180 列七页及关键浮层的当前屏幕、样式/主题证据、按键轨迹；旧图只标为 Before。
5. CLI 实际 stdout/stderr/退出码样本，名称+ID、错误恢复、机器输出和 watch 兼容证据。
6. 原生模块字段依据、覆盖边界、数据保真与固定真实 Xray loopback 结果。
7. URL 脱敏、IME、记录拆分等疑点的核验结论与剩余限制。
8. 与旧交互契约相比的必要变化，特别说明没有恢复快捷键长条、右侧详情、全局持久 Use/Edit 或保存即运行。
9. 下一轮独立审查所需的最小文件和可直接重复的隔离运行命令。

禁止以下“完成方式”：

- 为提高评分删除主题、隐藏模块或删掉复杂字段。
- 把缺少截图写成缺功能，把历史缺陷写成当前已确认问题。
- 只把 CURSOR 改名，把不同状态词强行统一，或用用户看不见的数据填充空白。
- 新增恢复到旧快捷键长条/右侧动作面板的第二套操作风格。
- 降低断言、删除失败测试或无说明重录所有快照来制造通过。
- 用测试数量、MCP 安装、两个 63 分、主观自评分代替修复证据。
- 将工程验证通过写成用户 G5 PASS。

最终说明实际修了什么、哪几项评审建议没有直接采纳及原因、剩余问题和如何体验。评分留给下一轮独立审查，G5 留给用户；本轮目标是消除已确认的产品缺陷，同时守住已有设计与数据边界。
