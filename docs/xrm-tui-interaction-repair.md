# XRM TUI 定向修复：Profile、焦点、底部信息与单视图编辑

**状态：依据用户最新实机截图和反馈制定的修复任务；不是实现完成声明。**

本轮只修用户已经指出的交互缺陷。沿用现有 Manager/Server、独立节点库、原生模块、多文件运行目录与独立 Xray-core，继续不使用 libXray。不新增架构阶段，不重新开发协议、订阅、测速、Geodata 或核心生命周期。

本文依据两张最新 Profiles / Modules 截图及用户本轮明确要求。旧 `codex-iteration-prompt.md` 中“数字捷径可保留”“宽屏结构/JSON 左右分栏”等约定被本轮明确替代；不再为了兼容保留这些旧操作。本文编写时没有访问当前实现仓库，具体故障函数及 `p` 失效根因需实施者用现有代码和真实终端确认。

## 1. 必须解决的问题

1. Profile 的查看、使用、编辑混在 Enter 中；仅使用已保存 Profile 也显示 editing。
2. 操作说明、原生键/路径、状态在内容区重复占行，底部提示又与实际焦点不符。
3. `p` 预设提示存在，但正确的内容操作链不可用或缺乏明确适用范围。
4. Modules 二级 Tab 仍能用上下键切换，与 Tab 分层导航冲突。
5. `1–9` 仍直接切顶级页；`[` / `]` 仍直接切二级页；焦点与实际事件接收者不一致。
6. 非 Content 焦点仍可以触发 Content 操作；一次事件可能在父子组件中重复生效。
7. 所谓“可视化编辑”仍像只读结构打印；结构与压缩 JSON 左右并排，不符合用户要求。

交付目标是以上问题全部修复后的真实操作，不是增加更多说明、快捷键别名或只修改 Focus 文案。

## 2. 本轮决定：一个明确的交互模型

- 顶级、二级、内容区严格分层。
- Tab / Shift-Tab 只在当前层内切换；Enter 进入下一层，Esc 返回上一层。
- 顶级和二级导航不保留方向键、数字键、方括号的替代切换路径。
- Content 命令必须同时满足页面、二级页、焦点、编辑状态条件。
- 文本输入优先处理普通字符；弹窗只接受自己的事件。
- 状态、文件路径、焦点、模式、通知和快捷键提示统一在底部呈现，不在中间堆说明文字。
- 模块主体只有一个全宽视图；F2 在可视化和 JSON 间切换，所有窗口宽度一致。
- 可视化必须能实际编辑，不以显示树和 JSON 的类型说明冒充编辑器。

## 3. Profile：View / Use / Edit / Connect 分开

### 3.1 用户操作

以下操作属于 **Profiles 页的 Content 焦点**，输入框/弹窗不继承这些字符快捷键。

| 操作 | 行为 | 不得发生 |
|---|---|---|
| 上下选择行 | 只改变列表高亮 | 不 Use、不 Edit、不启动 |
| Enter / View | 查看所选 Profile 的详情，只读 | 不把 Profile 标成 editing，不隐式使用 |
| `u` / Use | 选用该已保存 Profile，作为后续操作和连接的当前方案 | 不打开编辑器，不创建草稿，不修改模块内容 |
| `e` / Edit | 显式打开该 Profile 的编辑上下文，按需建立草稿 | 不改变当前使用方案，不切换运行核心 |
| 保存 | 只提交当前编辑的设置 | 不隐式 Use，不 connect/restart |
| 已有 Connect / Apply | 通过现有显式连接动作运行所选方案 | 不先强迫进入编辑状态 |

Profiles 中不再保留 Enter 同时 Select/Edit 的旧分支，也不额外保留多个等价 Use 快捷键。Nodes/Groups 原有的明确选择动作不因此被删除。

Use 的含义在本轮固定为“选择使用这份已保存方案”，不是自动连接。需要立即运行时用已有明确 Connect / 选用并连接动作。连接行为复用现有服务，不新增 Profile 专用运行后端。

### 3.2 状态不得混用

实现可以复用已有字段，但必须区分下面四种事实：

- 高亮对象：列表当前查看哪一行。
- 当前使用方案：后续 Connect 使用哪个 Profile。
- 编辑目标及草稿：仅在用户明确编辑时存在。
- 运行方案：由 Server 的实际 RunRecord 给出。

这些是 UI/现有设置的不同含义，不要求增加四张数据库表或新 SessionManager。

例：正在运行 A，用户高亮 B 并 Edit B，仍然使用/运行 A；保存 B 也不切换。用户 Use B 后，显示“使用 B，运行 A”；再明确 Connect，成功后才显示运行 B。失败时仍如实显示运行 A。

不要在“当前查看的 Profile”旁永久追加 `editing`。编辑状态应与真实打开的编辑上下文一致；未保存标记仅由实际草稿变化产生。

编辑 A 尚有未保存稿时切换目标，不得静默保存、丢弃或把草稿改绑到 B。复用现有一次保存/丢弃/继续编辑选择即可。

## 4. 完整焦点与键盘契约

### 4.1 允许的层内操作

| 焦点 | Tab / Shift-Tab | Enter | Esc | 上下等方向键 |
|---|---|---|---|---|
| TopNav | 前后切换顶级 Tab，焦点保持 TopNav | 有二级页则进入 SecondaryNav，否则进入 Content | 留在 TopNav | 不切任何导航、不移动隐藏内容 |
| SecondaryNav | 前后切换当前页二级 Tab，焦点保持 SecondaryNav | 进入该二级页的 Content | 返回 TopNav | 不切模块、不移动隐藏内容 |
| Content 非文本 | 切当前内容的可聚焦控件，不切页 | 操作当前对象/按钮/字段 | 先退出局部详情，再按层回到 SecondaryNav/TopNav | 只操作当前内容列表、树或滚动区域 |
| TextInput / JSON 编辑 | 遵循当前编辑控件，不切页面 | 编辑控件自身语义 | 结束当前编辑/关闭其层，不连续跳级 | 光标移动或本控件滚动 |
| Overlay / Dialog | 仅在当前弹窗内部切换 | 当前弹窗按钮/字段语义 | 关闭或取消本弹窗，恢复原焦点 | 仅影响弹窗内部 |

进入新一层的那个 Enter 必须被消费：TopNav 的 Enter 不能同时打开模块字段编辑，SecondaryNav 的 Enter 不能同时选用节点。Esc 同样一次只返回一层。

Tab 切顶级页面只更新显示的页面，不让新页面开始接收 Content 命令。切二级模块同理。无二级导航的页面不能创建看不见的中间层。

### 4.2 明确移除旧切换入口

删除所有以页面/模块切换为目的的：

- 数字 `1–9` 直达顶层页；
- `[` / `]` 直达二级页；
- 导航组件默认的 Up/Down/Left/Right 模块切换；
- 与这些行为等价的旧兼容分支。

不是“数字切页后顺便修复 Focus”，而是彻底删除这些直达键位。顶栏相应删除暗示数字快捷键的 `1 Overview`、`2 Profiles` 等前缀；选中项仍可用 `[Profiles]` 作为显示标记。

这不是全局禁用数字或方括号：JSON、字符串、数组、端口输入中的 `123`、`[1,2]` 必须照常可输入。只删除导航动作。

### 4.3 内容命令示例与作用域

| 按键 / 动作 | 允许上下文 |
|---|---|
| Profiles `u` / `e` | Content + Profiles 列表，非文本输入 |
| 节点选择、连接、测速 | Content + 对应 Nodes/Groups 功能，非文本输入 |
| Routing `p` | Content + Modules + routing + 可编辑的 Source 目标，非文本输入 |
| Logs `p` | Content + Logs，非搜索/文本输入；只切 Pause/Follow |
| 模块 F2 | Content + Modules，切当前可视化/JSON视图；见第7节 |
| 模块 Ctrl-S | 该内容编辑上下文中的 Source 草稿保存 |
| F6 外部编辑器 | 模块 Source 编辑上下文；复用已有实现 |
| `q` 退出 | TopNav 中的明确退出动作；输入/弹窗不穿透，Content 不追加隐式全局退出 |
| F1 / 非文本 `?` | 仅显示当前层的帮助，不先触发下层操作 |

旧内容帮助里的 `s/c/t/p/e` 等不得在 TopNav / SecondaryNav 显示成当前可用命令。源/运行切换是独立操作；既有 `v` 若继续用于该操作，只在对应内容非文本态使用，不能同时作为外部编辑器或 F2 的旧别名。

### 4.4 事件分发的实施边界

先查当前根事件处理、各页处理器、Menu/Container 默认键位。Focus 不能只是一条用来显示的字符串；实际事件接收者必须跟随它。

用已有 enum 和一处集中的路由协调即可，逻辑等价于：

```text
有活动弹窗？只交给弹窗，结束。
否则有活动文本输入？按输入控件规则处理普通字符和允许的编辑动作，结束。
否则按当前 FocusScope：
    TopNav       -> 只处理顶级导航
    SecondaryNav -> 只处理二级导航
    Content      -> 只处理当前内容
```

F2/Ctrl-S 等明确编辑动作可由当前编辑上下文处理，但不能从任意页面或层级全局触发。

**当前层没处理，不等于允许向隐藏下层继续广播。** 特别检查“返回 false 后框架默认 Menu 又处理方向键/Enter”的路径。需阻断时在本层消费事件，而不是只加一个 if 后仍放行。

异步通知、外部编辑器返回、窗口缩放不能偷走焦点。弹窗关闭恢复原 scope/控件；通知不成为新的焦点层。

不新增通用快捷键 DSL、事件总线、插件系统或状态机框架。少量当前上下文动作描述可同时供 footer 与按键处理使用，防止二者再次不同步。

## 5. 内容区与底部信息重新归位

### 5.1 内容区允许显示

Profile/节点表格及详情、真正可编辑的字段/结构、格式化 JSON、日志正文、真实统计图表、预设列表与预设差异内容。表头、搜索框、字段标签是内容的一部分。

### 5.2 从内容区移走的文字

包括截图中的：

```text
Profiles - Enter switch browsing context; n create; ...
Profile browsing does not connect, save other drafts, ...
Native Modules · 15 Xray root keys · Tab changes module ...
Native key: log · included · source exists
source: modules/00_log.json · runtime: 00_log.json · v switch ...
e Enable/Disable · Enter Edit Native · F6 ...
```

这些是上下文、状态或操作提示，不是内容正文。移到统一 footer/上下文帮助中，不在中部各页面继续生成独立说明行。

底部状态和操作提示必须随当前焦点和页面变化。信息多时做精简与按需详情，不把全部元信息硬塞成长行，也不让一次通知把操作提示永久挤掉。

### 5.3 布局约束

- 顶部：紧凑的顶级 Tab，紧邻本页二级 Tab；不保留无用途大空行。
- 中部：一个主内容区域，独立滚动。
- 底部：通常2–3行，分别容纳简要状态/操作结果、必要位置/模式、当前有效操作；以80×24实测调整。
- 路径、Focus、Source/Runtime、Visual/JSON、included、dirty、期望/实际 Profile 等只在 footer 或明确展开详情呈现，不重复成中部横幅。
- 本轮要求说明/状态信息放底部：旧通知位置与此冲突时改用现有 footer 的临时消息位，不再建设另一套通知服务。详细错误通过现有详情动作打开，不无限堆积。
- 底部操作说明只出现本层可用项；非适用的 `p Preset` 不显示，不能靠用户猜何时会生效。
- 模块关闭但有原文时仍可查看/编辑；未创建时显示内容级空状态与创建按钮，不自动启用。

## 6. `p` 预设：修复真正的用户入口

截图同时显示 `log`、`Focus: TopNav` 和 `routing: p Presets`，容易让人认为此时就能打开预设。修复必须同时解决**适用上下文提示**和**正确上下文中的实际可操作性**。

标准流程：

```text
TopNav 用 Tab 选 Modules
Enter -> SecondaryNav
Tab/Shift-Tab 选 routing
Enter -> Content
p -> 打开 Routing Presets 选择器
选择预设 -> 看可读原生差异
确认 -> 进入同一模块草稿 / 明确保存
```

要求：

- TopNav / SecondaryNav 的 `p` 不应执行内容命令；不是为了修复失效就把 p 注册成全局。
- 非 routing 模块不显示 Routing Preset 的可执行提示。
- routing Source Content 的 p 必须可打开选择器；disabled但可编辑的source不因“未参与运行”而禁止打开编辑工具。
- JSON/字符串输入中的字母 p 是文本，不打开预设。
- Runtime 只读预览不允许预设改运行文件；相关提示不显示或明确要求切回 Source。
- 取消预设不改源模块、不丢原草稿；确认动作复用已实现的 preset plan/diff/save 路径。
- 保存只改实际目标 routing 模块，不启动/重启核心，不修改无关模块。
- 若依赖缺少，展示明确原因，不吞按键；不自动下载资源或改其他 Profile。

实施者需报告实测根因，不能没有源码证据就断言一定是某个全局 handler 或 Geodata 问题。

## 7. 单视图可视化编辑 / 格式化 JSON

### 7.1 展示方式冻结

所有尺寸下都只有一个主视图：

```text
F2 -> Visual
F2 -> JSON
F2 -> Visual
```

不再采用“宽屏左右分栏、窄屏才切换”。不再左边一棵只读树，右边放一行压缩 JSON。

两个独立维度不能混淆：

- 文档目标：Source draft / Runtime read-only。
- 展示模式：Visual / JSON。

F2 只改变第二个维度，不切换源/运行，不切换 Profile，不保存、不连接。Runtime 的 Visual 也必须只读。

### 7.2 Visual 必须实际可编辑

复用并补齐现有结构编辑器，不重写IDE。最少实现：

- 标量：string / number / boolean / null 的真实编辑，布尔值可切换且类型保持。
- 对象：添加键、改名、删除；重名给局部错误，不覆盖其他字段。
- 数组：添加、删除、复制、上移/下移；保留顺序语义。
- 对象/数组展开收起，字段通过内容区方向键和焦点操作。
- 现有模块专用表单优先复用；高级字段通过同一个结构组件处理。
- 未知字段与真正的 JSON 类型不丢失；不发明 Xray 字段或自动填“安全”默认。

对 `log` 至少可直接编辑 `loglevel`，例如选择 info/debug 后实际改变草稿。不接受只显示 `loglevel: string = "info"` 却仍只能去JSON输入的“可视化编辑”。

Screenshot中的`log → log → loglevel`若来自模块wrapper被重复包裹，应去掉重复层。可以显示一次原生根键或模块内部字段，不能渲染两层同名伪对象。

### 7.3 JSON 必须默认可读

合法 JSON 采用2空格缩进、多行、真实Unicode字符，数组和对象按层级展开。可滚动，长字符串可横向查看或进行显示层软换行，不能为了适配窗口截断实际数据。

例如应显示：

```json
{
  "log": {
    "loglevel": "info"
  }
}
```

而不是默认显示 `{"log":{"loglevel":"info"}}` 这一行。

显示格式化不能自动改写源文件。只是进入JSON预览、切换F2或退出预览，不标 dirty、不发保存RPC。可以按需生成只用于展示的formatted projection；明确进入文本编辑并改动后才成为草稿变更。

### 7.4 同一草稿，不新增双向同步系统

Visual、JSON和外部编辑器共用当前ModuleDraft。允许使用原文与按需解析缓存表达同一草稿，但只有一个可写来源；不新增两份独立可保存的配置。

- Visual改字段 -> JSON切换后显示该改动。
- JSON改合法内容 -> Visual切换后显示该值及其类型。
- JSON无效 -> 保留文本与草稿，底部显示行列/错误；留在JSON模式，不用上次有效树覆盖当前文本。
- Ctrl-S只提交当前Source模块；其他模块、当前Use Profile和正在运行的核心不随之改变。
- Runtime只读视图不能通过切F2或外部编辑器绕过只读。
- 只是显示模式切换不删除源注释。结构化实际编辑需要规范化当前源时，按既有规则明确说明，只涉及当前模块，不建设CST或注释重建器。
- `stats: {}`、FakeDNS对象/数组、原生未知字段及routing规则顺序继续保留。

## 8. 实施步骤和修改边界

1. 先复现用户截图中的Profiles/Modules操作，在现有真实PTY记录当前失败。
2. 先读主事件分发及默认组件事件；由一个owner修改共享焦点/键位和footer。
3. 将View/Use/Edit拆成现有状态与动作的明确分支，修复Profile行状态文案。
4. 清理所有旧导航快捷键与旧帮助文案，不仅修其中一个页面。
5. 修routing preset入口并复用已有预设逻辑。
6. 改单视图切换，补齐真实Visual编辑及JSON多行格式化。
7. 更新当前操作说明与冲突测试；保留历史测试通过记录，但不将旧行为继续当本轮正确标准。
8. 同一集成分支做当前画面检查及回归，报告实际问题与修复。

优先复用当前 `src/tui/app.*`、`state.*`、`actions.*`、Profiles/Modules/Logs页面和已有JSON/editor组件；具体文件以仓库为准。除非现有RPC确实不能表达独立Use选择或现有preset能力，不改Server业务接口。

一个文件一个owner。共享TuiApp/焦点/键位/草稿集中修改，不让五个子Agent同时改app.cpp。最多并行一个独立测试分支或只读审查；不要重新派整轮M0–M5任务。

不改节点匹配、协议、核心安装、生产网络设置、资源更新流程。旧资料中已被本轮否定的键位/左右分栏预期应据此更新，但不得削弱真实保存、连接、marker断言。
