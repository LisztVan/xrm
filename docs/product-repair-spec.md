## 1. 当前结论与证据边界

用户实际使用报告了：常见 VLESS 订阅节点无法正常导入、打开 disabled 原生模块时 TUI 崩溃、TUI 启动依赖用户预先提供 Profile UUID、内嵌原生编辑器体验不佳。因此当前状态是 **G5 FAIL：主流程不可用**，不是“只差人工签字”。原有自动测试通过记录仍然有效，但只能证明其实际覆盖的场景，不能替代这些失败。

本文件根据用户报告、已确认的需求/架构以及官方资料制定修正。作者本次没有访问实现仓库，没有取得八条完整 URI，没有运行用户二进制，不能断言具体崩溃根因，也不能保证八条节点修正后全部可连接。尤其 TLS insecure=true 的实际意图需要逐条区分。

过去的 M0–M5 分工是执行计划，不是禁止修复的永久边界。修复已经承诺的 VLESS、Profile 操作、模块状态和编辑体验属于交付缺陷修复。不得仅以“G5 不允许扩展协议”为由只做诊断。真正新增 AnyTLS、多核心、Web 平台等仍然不在范围内。

本文件对冲突处优先于旧文档的过严参数拒收和手输 Profile ID 假设；其余架构保持。实施时只修改相关需求、接口、测试与说明，不删除旧证据或重写全套架构，不新增 changelog 平台。

## 2. 用户流程是首要验收对象

在 Server 已运行的正常安装环境中，用户只应需要：

```text
xrm tui
  → 订阅 → 添加 → 粘贴链接 → 保存
  → 更新 → 在节点页看到实际结果与有意义的名称
  → 选择节点或策略组 → 连接
  → 查看日志、统计、状态
```

首次无 Profile、无节点、无核心登记时，界面必须仍可打开。缺少的必要条件通过页面和一次性的设置引导处理，不能让用户退出软件去查 UUID。订阅是共享资源，不要求先有 Profile 才能添加和更新。

连接前可以查看、调整 DNS、routing、策略组、observatory 及其他原生模块。默认配置方案应当足够完成明确的本地代理，不要求新用户手工编辑所有模块才能首次连接。默认模板是可见、可编辑的普通原生模块文件，不是隐藏配置；不得自动接管系统 DNS、防火墙或 TUN。

核心未登记时引导选择现有 Xray 或现有安装功能；Server 不可达时明确说明连接位置与启动动作，不崩溃，不自动提权安装系统服务。

## 3. Profile 是界面可操作的配置方案，不是启动口令

### 3.1 TUI 入口

- `xrm tui` 为完整入口，`--profile` 为可选定位参数。
- 首次无 Profile：显示“创建配置方案”，可使用已有 local 预设创建可读名称（如“默认”）；也允许先处理订阅。
- 只有一个 Profile：自动在界面中选择它，不自动连接。
- 多个 Profile：恢复上次有效选择并提供显眼的切换入口；无有效选择时展示列表，不要求用户输入 UUID。
- 顶部显示正在编辑的 Profile 名称；若实际运行的是另一 Profile，单独显示，不能把浏览切换等同运行切换。
- Profile 页可创建、复制、重命名、选择、删除，并能看见哪个在运行。
- 切换浏览上下文不重启核心、不自动保存其他草稿；只有明确的连接/应用动作改变运行。

UUID 保留作内部稳定身份，脚本仍可使用精确 ID。人类入口支持唯一可读名称与列表选择；重名时列候选，不随意选第一个。CLI 非交互且名称歧义时清楚报错；不能突然要求脚本交互。既有按 ID 调用保留兼容，不需要更换全项目身份模型。

### 3.2 最小实现边界

继续使用 ProfileService、现有 Profile 索引和 RPC。补足 Profile 列表/选择/创建入口及客户端当前上下文；不建立全新的 SessionManager、路由器式状态平台或复杂 Profile 继承。若需记忆上次选择，只保存这一项偏好，不创建第二份 Profile 数据。

## 4. VLESS 导入：依据语义兼容，不依据陌生参数名整条拒收

### 4.1 三层依据，不混淆

1. 官方分享链接规范说明 URI 参数含义。[S1]
2. 原生模块/传输文档说明应输出的 Xray 字段、层级和含义。[S2–S7]
3. 所选核心的固定源码与实际运行确认该版本接受并执行的行为。[S8]

查询时官方发布列表首项仍是 v26.9.9（Pre-release）。继续以已验证的 v26.9.9 为本次回归基线，不把 main 与其混用，不为了修复导入悄悄更换核心。[S10]

参考其他客户端只用于识别实际生态中出现的 URI 形态。例如 v2rayNG 当前 FmtBase 明确读取 headerType/quicSecurity、ECH、证书固定等参数，并会导出 TCP 的 headerType=none。[S9] 这不是照抄其解析器的理由，也不把客户端行为当核心配置规范。

### 4.2 参数处理分四类

| 类别 | 默认行为 | 不能做什么 |
|---|---|---|
| 官方参数且所选核心支持 | 正确解析并映射；正常导入 | 以当前 struct 没字段为由称核心不支持 |
| 已知旧别名、当前传输无效项或等价默认项 | 按明确上下文归一化，必要时给简洁说明；正常导入 | 只看参数名就拒收，或猜测任意未知值都可忽略 |
| 真实影响连接，但尚未支持、含义不确定或参数冲突 | 在导入报告/待处理项中保留并指出具体字段，不作为可连接节点 | 整份订阅全部作废、伪造可执行节点、静默降级 |
| URI/端口/编码/认证结构损坏 | 报准确的解析错误，保留其他有效条目 | 用 unknown parameter 混淆真正格式错误 |

真正未知参数不自动当成无害，也不必把识别到的整个节点永久丢掉。导入报告保留足够的信息用于修正或重新解析；能明确构造的节点正常入库。待处理项不能进入自动组或运行 FileSet，也不以假的 RawOutbound 冒充成功。

使用现有 ParseReport/issue 数据即可；必要时只补一项兼容状态或导入备注。不要开发通用策略引擎、版本能力注册中心或节点审核平台。

### 4.3 本次参数处理表

下表的兼容策略是 XRM 的明确产品要求；不是宣称每个旧参数均属于官方分享规范。

| 参数/上下文 | 修正要求 |
|---|---|
| `type=tcp/raw` | 归一到所选核心支持的 RAW；保留当前核心已接受的输出命名，不改 server/address 语义。[S3][S8] |
| `type=ws/websocket`、`xhttp/splithttp` | 识别经核对的别名，输出各自对应 transport，不能统统当 raw。[S8] |
| `headerType=none` + RAW | 无头部伪装；与默认 NoneHeader 等价，接受。[S3] |
| `headerType=none` + WS/XHTTP | 作为已知模板残留的无效默认项接受，不注入 RAW header、不删除 WS/XHTTP 的 host/path。该项是有条件的兼容规则。 |
| `headerType=http` 等非默认值 | RAW 下可能有真实头部语义；按规范/既有生态形态实现或明确指出未支持项，不使用“none 的忽略规则”。 |
| `quicSecurity=none` + RAW/WS/XHTTP | 视作旧 QUIC 模板默认残留，接受；不把它写入 TLS 或 XHTTP。其余值和真正 type=quic 分开处理。 |
| `type=quic` 或旧 `http/h2/h3` transport | 固定 v26.9.9 的 transport switch 将其作为移除项；不能等同支持中的 XHTTP/H3，也不能无提示改成 XHTTP。[S8] |
| `insecure=false/0`、兼容别名为 false | 接受；保持证书验证，不为它生成 allowInsecure=true，不报“未知字段”。别名识别是兼容层，不写成新原生键。 |
| `insecure=true/1` + TLS | 不能直接判定等价于可用的 allowInsecure=true。官方规范说明该旧行为已移除/弃用；先据固定核心确认，再明确要求可用的信任参数或由用户显式选择正常证书验证，不静默变更。[S1][S2] |
| `insecure=...` + REALITY/无 TLS 的传输安全上下文 | 已知的普通 TLS 验证开关不应把整个节点变成未知协议错误；在确认当前上下文确实不使用该普通 TLS 设置时，可忽略并说明。不改变 REALITY 认证参数。 |
| `ech` + TLS | 按官方映射写入 tlsSettings.echConfigList；不属于未知扩展。内容不能当通用 true/false。[S1][S2] |
| `sni` / 经确认的 `servername` 兼容别名 | 映射 serverName；同时存在且一致可合并，不一致明确提示，不能随意覆盖。 |
| `fp`、`alpn` | 正确映射 TLS/REALITY 对应字段；ALPN 按规范分隔，不把缺省/空串/列表混为一谈。[S1][S2] |
| `pbk`、`sid`、`spx`、`pqv` | REALITY 认证/身份/路径/ML-DSA 参数按当前原生字段映射；名称旧不代表参数无效。[S1][S4] |
| `encryption`、`flow` | 不只允许 encryption=none；当前核心支持的 VLESS Encryption 字符串和 flow 必须保留并交核心处理，不自行实现加密或无提示清掉 flow。[S5] |
| `path`、`host`、`mode`、`extra` | 按实际 transport 解释；XHTTP extra 保留其 JSON 结构，mode 不同传输含义不同，不相互套用。[S6][S7] |
| `serviceName`、`authority`、gRPC mode | 遵循 gRPC 原生映射，不因主流程优先 RAW/WS/XHTTP 就把已承诺 gRPC 字段伪装成无效输入。 |
| `pcs`、`vcn` | 证书固定与证书名称验证，按原生字符串传递；不能用空证书固定值模拟不校验证书。[S1][S2] |
| `fm` | 完整解析 JSON 后写对应 streamSettings.finalmask，不新建顶层 fm/finalmask 模块。[S1] |

布尔兼容层接受明确的 true/false/1/0；不把任何非空字符串都当 true。常量大小写、别名集合以及空值处理需逐项说明，不能将整个 URI 参数字典 lower-case 后破坏值。

官方规范禁止重复字段。为兼容重复同值可给 notice 后归一；重复或别名的不同值不能继续沿用“最后一个悄悄赢”的规则。只改相关参数冲突处理，不开发任意优先级系统。[S1]

### 4.4 ECH 的具体注意事项

ECH 原生值支持固定配置以及通过 DNS 获取配置的字符串形式，后者还可包含指定查询域名与查询地址的组合。[S2]

因此实现必须：仅按 URI 组件 percent-decode 一次；保留值中的 `+`、`/`、`=`；query 仅在第一个 `=` 分离 key/value；不得套表单 URL 解码把 `+` 改空格；不得把 ECH 字符串强行解成普通 Base64 JSON。空 ech 也不能仅因为空拒收。

ECH 没有适用 TLS 上下文或内容有真正格式问题时应给具体原因。此处没有八条原始值，不能凭“带 ech”推定都合法，也不能凭“带 ech”推定都不兼容。

### 4.5 insecure 必须诚实处理

TLS 页面仍保留旧 allowInsecure 的说明/示例，同时注明弃用；分享规范也明确指出其移除。[S1][S2] 不得因为旧示例里出现此键，就把 true 写回当前运行配置并称兼容已完成。

对于 TLS 节点确实要求跳过验证而目标核心不能表达的情况：保留为待处理，指出“该验证方式不受当前核心支持”；可提供使用正常验证、导入可信 CA 或固定经确认的证书等明确修正入口。不同信任方式不是无损同义替换。禁止自动从一次未验证连接取得证书后当作可信 pin；不修改订阅 HTTP 的正常 HTTPS 验证设置。

若已有可信 pin 且用户选择采用 pin，按此明确选择生成当前配置，不宣称完全复现了原来的跳过验证。不要把现实上可能仍能正常验证的节点自动永久丢弃，也不要替用户无声改变验证模式。

### 4.6 完整链路必须保留参数

```text
URI → Codec → Node/原生子对象 → Store 保存和重读
    → 节点编辑（只改指定字段）→ RuntimeAssembler → 节点出站文件
    → 实际 Xray 检查与流量
```

重点检查高级字段是否在 Store 或表单保存时丢失；不能只让 parse 函数返回 ECH，后面的序列化又将其清空。继续单一节点模型与已有 TLS/传输扩展区域，不再维护两份可写的同义参数。

## 5. 模块体验必须保留，disabled 模块是正常数据状态

原生模块与多文件输出是本项目保留的核心优势。不能为修复 TUI 放弃模块页、合成单 JSON，或强制全部模块启用。

打开模块时至少区分下列状态：

| 模块情况 | Enter 后的行为 |
|---|---|
| included=true，已有正文 | 查看/编辑该正文 |
| included=false，已有正文 | 查看/编辑已保存正文，同时显示“未参与运行”；不自动启用 |
| included=false，没有源文件 | 显示未配置状态、模块说明与“创建配置/编辑”入口；不崩溃，不自动写盘 |
| included=true，没有必要正文 | 展示待补齐状态；允许创建/修复，不解引用空对象 |
| 源文暂时无效或无法用表单解析 | 原文仍可查看修正；表单说明限制，不能终止整个 TUI |
| 模块/源文件被另一客户端删除 | 刷新并提示对象已变化；保留未保存稿件 |

检查实际堆栈定位根因；不能在未查看实现时声称一定是某个 optional 或索引错误。修复应落在共用模块详情/编辑入口的数据状态处理中，不能为 15 项各塞一层 catch-all，也不能捕获异常后假装操作成功。

保持模块页的原生 key、中文作用说明、启用状态、源文件/运行文件及高级字段。让用户知道修改了什么，是功能的一部分。

## 6. 编辑器：常用表单可用，原文编辑不当成迷你 IDE

### 6.1 页面行为

- 明确显示“表单 / 原文 / 外部编辑”入口和快捷键，而不是只有隐藏的 v。
- 复杂原生 JSON 优先提供用户已配置的外部编辑器；内嵌编辑保留可用基本体验，不重新实现 Vim/Emacs。
- 设置页可选择并保存 editor argv；已有明确选择优先，其次沿用 VISUAL/EDITOR。未配置时给可操作引导，不让普通编辑变成神秘报错。
- 外部编辑返回草稿，显式保存再修改源模块；仍然不自动应用/连接。

### 6.2 内嵌编辑器的最低要求

换行、方向键、Home/End、翻页、退格/删除、长行滚动、Unicode 光标移动、整段粘贴、撤销、清晰保存/取消、未保存提示。支持当前终端的正常粘贴路径，不能把粘贴的字符当一串全局快捷键。无法可靠支撑长内容时直接提供外部编辑，不继续叠加复杂编辑器框架。

Ctrl-S 等绑定必须在真实终端可用；不能只在 PTY fixture 中关闭流控后报告成功，却要求用户自己运行 stty 才能操作。终端状态处理由 Manager 按现有终端库管理并在退出后恢复。若无法确保特定组合，提供同等明确的菜单/其他键，不把它作为唯一保存入口。

本次修正不要牺牲已实现的日志暂停、外部编辑恢复和冲突草稿保留。

## 7. 测试从人为准备好的 fixture 转向真实首用路径

旧测试保留。它们的预设如果错误地要求“未知参数一律拒绝”，应根据这里的参数规则和官方依据修正，记录原因；这不是降低标准。禁止改实际流量断言来掩盖仍然错误的转换。

本次优先增加以下四组回归，不建设新的证据平台：

### A. 本次实际订阅形态

取得当前开发环境已有导入记录或用户明确提供的脱敏文本；不擅自访问所有真实订阅。至少重现这八条的字段组合与传输类型，而不是只补一条 headerType=none。

脱敏时替换真实端点、UUID、密钥与 pin，保留参数集合、编码形式、空值、冲突与 transport/security 组合。需要握手的样例使用本地生成且成对匹配的密钥/证书。保留原始值的受限本地诊断与可提交测试 fixture 分开，禁止把真实凭据提交仓库。

断言：适用参数正确输出；无效默认项不拒收；ECH 的特殊字符完整；true/false 语义不同；未知影响项保留待处理；其他有效节点正常入库；刷新不改变运行进程和 FileSet。

### B. 无 Profile 的完整首用

清空隔离测试数据；启动真实 xrm/xrmd；直接 `xrm tui`，不传 ID、不用测试提前创建 Profile。

在 UI 添加本地订阅地址、更新、查看正常节点、在界面创建/选择配置方案、选节点并连接；看到日志/统计。名字、UUID、Profile 路径都不能靠测试人员手工拼接给用户路径。

### C. 所有模块的正常空状态

对原生清单逐项测试：disabled+无源、disabled+有源、enabled+有源；再测试无效源和外部删除。真实按 Enter 打开、返回、重复切换，dev/ASan 都不能崩溃。断言未暗中启用或创建文件、未改变运行配置。

### D. 用户实际使用的 VLESS 传输

现有 VLESS RAW loopback 不足以代表 WS/XHTTP 全支持。至少为本次涉及的 RAW、WS、XHTTP 建立适用的本地真实核心客户端/服务端链路，走 URI→库存往返→多文件→连接，验证 marker。

TLS/REALITY 只选择官方支持的组合，不强行交叉全部传输；信任由隔离的本地证书/测试CA或明确 pin 建立。ECH 的导入/持久化/输出先做确定性测试；声明 ECH 握手可用前再做对应的本地实际测试。不能因普通 XHTTP 可连接就写“所有 ECH 节点已验证”。

真实用户订阅最终连通测试由用户发起或明确授权后执行；本机用例证明修复行为，不宣称远端线路一定在线。

## 8. 执行顺序与文件归属

不重做原项目 DAG。使用一次限范围的缺陷修复批次：

| 优先级 | 工作 | 主要归属 |
|---|---|---|
| P0 | disabled 模块 Enter 崩溃，先复现并修复 | TUI 模块详情/动作；必要的 ProfileService 状态返回 |
| P1 | VLESS 语义兼容与完整参数往返 | 现有 vless/stream Codec、解析报告、必要 Store 序列化、独立 fixture |
| P1 | 无参数 TUI 入口与 Profile 页、首次订阅到连接 | Manager 启动、Profile 页面、CLI 名称解析、现有 RPC/Application |
| P2 | 原文编辑体验与显眼外部编辑入口 | Manager 编辑器和模块页，不动核心组装 |
| 收口 | 新用户完整回归和人工重验 | 主 Agent 集成，更新实际支持范围与验收文档 |

最多两个实现分支并行：Codec 与 UI；共用 TUI app/actions 文件同一 owner，Profile 与编辑器改动由同一 UI 任务顺序集成。主 Agent 统一修改共享声明和构建配置。只读审查可另行安排，不为修复重建五个开发阶段。

先为每个报告缺陷写可失败的回归，再改实现。检查真正已有代码，不按猜测添加新的组件层。保留已验证基础设施与模块体系。

## 9. 需要同步修正的项目文档

- requirements.md：无参数 TUI 与首用流程、Profile 可见管理、disabled 模块行为、VLESS 兼容策略。
- architecture.md / implementation-plan.md：局部补充启动上下文、导入 issue 分类和 module empty 状态，不改变 Manager/Server 与 FileSet 边界。
- testing-standard.md：加入本次实际字段组合、零准备首用和空模块按键测试；错误的旧拒收预期应有来源说明后更新。
- AGENTS.md：已承诺功能的崩溃、兼容性和使用路径缺陷不受已完成里程碑阻断；有授权后实施最小修复，不能只输出诊断。
- release-acceptance.md：当前人工验收为 FAIL；逐项记录修复和自动证据，用户重新操作后才能关闭人工失败项。

不把这些修正写成“已修好”。不因为测试数量增加就自动恢复 G5 PASS。config-verified 与 traffic-unverified 仍可用于说明实际证据，但不能用重新贴标代替修复本次承诺支持的常用 VLESS。

## 10. 完成条件

1. 用户直接运行 xrm tui 可开始工作，无需手输 Profile UUID。
2. 从未准备 Profile 的界面内可完成添加订阅、更新、选择、连接；可见管理并切换多个 Profile。
3. 本次所有 VLESS 字段组合逐条给出处理结果：可映射、等价兼容、待修正或确实不支持；不能再统一报未知参数。
4. RAW/WS/XHTTP 的实际支持范围有相应真实核心证据；未验证部分如实说明。
5. 15 个模块的 disabled/空源/有效源状态均可安全打开，保持可编辑与是否输出两个概念分离。
6. 原生模块、独立节点库、多文件组装、更新不重启等已有优点不退化。
7. 编辑器在实际终端可用；外部编辑入口可发现，保存仍不自动连接。
8. 自动回归通过后交付可直接使用的启动方式，用户重新执行真实人工流程；人手失败未关闭前不宣布 G5 PASS。
